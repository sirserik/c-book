Часть 0 пройдена — у вас в голове устройство компьютера, биты, алгоритмическое мышление, терминал, модель компиляции. Теперь начинаем собственно C++ — Часть I, чистый язык, без проекта. Семь глав, в которых разберём базовые конструкции, чтобы к Части II (RPG-игра) подойти подготовленными.

Первая глава Части I — про **типы и переменные**. В Python вы пишете `x = 5` и не задумываетесь, что это число какого-то размера. В C++ всё иначе: при объявлении переменной вы обязаны сказать, какого она типа. И типов целых чисел — пять штук, разных размеров. И ещё типы дробных. И ещё `bool`, `char`. И ещё способы их инициализации — три разных. И ещё `const`, `constexpr`, `auto`. Глава длинная, но через неё надо честно пройти, иначе вся арифметика дальше будет «магией».

## Почему в C++ типы такие важные

В Python `x = 5; x = "hello"` — нормально. Переменная меняет тип на лету. В C++ так нельзя. После `int x = 5;` переменная `x` навсегда `int`. Попытка `x = "hello";` — ошибка компиляции.

Это нужно по двум причинам.

**Производительность.** Когда компилятор знает, что `x` — это 4-байтное целое, он генерирует машинный код, специально работающий с 4-байтными целыми. Никаких проверок «а вдруг это строка?», никаких словарей типов в рантайме. Поэтому C++ так быстр.

**Безопасность.** Компилятор находит много ошибок ещё до запуска. Если функция ждёт `int`, а вы пытаетесь передать строку — компилятор ругнётся. В Python такая ошибка вылезла бы только при запуске, и то — если до этого места выполнение бы дошло.

Цена — больше работы при написании кода и больше синтаксиса. Но это того стоит. Особенно когда программа дорастает до сотен тысяч строк.

## Целые числа: семейство int

Начнём с самого частого. **Целое число** в C++ можно объявить пятью способами:

```cpp
char        c = 1;     // 1 байт
short       s = 1;     // 2 байта
int         i = 1;     // 4 байта (обычно)
long        l = 1;     // 4 или 8 — зависит!
long long   ll = 1;    // 8 байт
```

Главный сюрприз: **размер этих типов не зафиксирован стандартом C++**. Стандарт гарантирует только некоторые минимумы и порядок:

- `char` — ровно 1 байт, как минимум 8 бит (де-факто на всех платформах = 8 бит).
- `short` — как минимум 16 бит.
- `int` — как минимум 16 бит.
- `long` — как минимум 32 бит.
- `long long` — как минимум 64 бит.

И ещё гарантия: `sizeof(char) ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)`.

На практике на современных 64-битных системах:

| Тип | Linux/macOS x86-64 | Windows x86-64 |
|-----|--------------------|-----------------|
| `char` | 1 | 1 |
| `short` | 2 | 2 |
| `int` | 4 | 4 |
| `long` | **8** | **4** |
| `long long` | 8 | 8 |

Видите ловушку? **`long` под Linux/macOS — 8 байт, а под Windows — 4!** Поэтому полагаться на размер `long` нельзя. Если вам нужно ровно 8 байт — используйте `long long`. Если ровно 4 — `int`.

### Проверяем sizeof

`sizeof` — оператор C++, возвращающий размер типа в байтах. Используется так:

```cpp
#include <iostream>

int main() {
    std::cout << "char:      " << sizeof(char) << "\n";
    std::cout << "short:     " << sizeof(short) << "\n";
    std::cout << "int:       " << sizeof(int) << "\n";
    std::cout << "long:      " << sizeof(long) << "\n";
    std::cout << "long long: " << sizeof(long long) << "\n";
    return 0;
}
```

Соберите и запустите. На моём Mac M3 вывод:

```
char:      1
short:     2
int:       4
long:      8
long long: 8
```

`sizeof` — это **оператор времени компиляции**: компилятор вычисляет размер на этапе сборки и подставляет уже число. Поэтому `sizeof(int)` стоит ровно столько же, сколько просто литерал `4` — никакой работы в рантайме.

Можно применять `sizeof` и к переменной: `sizeof(x)` или просто `sizeof x` (без скобок). Тип переменной известен компилятору, размер он подставит.

### signed и unsigned

По умолчанию все целочисленные типы — **со знаком** (signed). То есть могут хранить и положительные, и отрицательные значения. Можно явно сказать «без знака»:

```cpp
unsigned int ui = 1;
unsigned long ul = 1;
unsigned char uc = 200;
```

Размер тот же, но интерпретация другая (вспомните главу 2 — дополнительный код).

| Тип | Размер | Минимум | Максимум |
|-----|--------|---------|----------|
| `signed char` | 1 | -128 | 127 |
| `unsigned char` | 1 | 0 | 255 |
| `signed short` | 2 | -32 768 | 32 767 |
| `unsigned short` | 2 | 0 | 65 535 |
| `signed int` | 4 | -2 147 483 648 | 2 147 483 647 |
| `unsigned int` | 4 | 0 | 4 294 967 295 |
| `signed long long` | 8 | -9.2 × 10¹⁸ | 9.2 × 10¹⁸ |
| `unsigned long long` | 8 | 0 | 1.8 × 10¹⁹ |

Можно сокращать: вместо `signed int` пишут `int`, вместо `unsigned int` — `unsigned`. Это эквивалентно. Но я рекомендую писать `unsigned int` или `unsigned long`, потому что одно слово `unsigned` без типа выглядит загадочно.

### Когда использовать unsigned

Естественное чувство: «если число не может быть отрицательным — берём unsigned». Возраст, количество чего-то, размер массива.

В C++ совет: **берите signed, даже если число всегда неотрицательное**. Парадокс? Объясню.

Главная причина — **arithmetic underflow с unsigned работает «странно»**. Возьмём пример:

```cpp
unsigned int i = 0;
i = i - 1;
std::cout << i;   // напечатает 4294967295!
```

Что произошло? `0 - 1` для unsigned даёт `2^32 - 1` (обернулось через ноль). Это, между прочим, **строго определённое поведение** для unsigned, не undefined behavior. Стандарт говорит: «арифметика unsigned — по модулю 2^N, где N — число битов».

Но из-за этого вы получаете «странные» баги. Самый известный — цикл назад:

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};

// Идём по вектору в обратном порядке, типичный новичковый код:
for (unsigned i = v.size() - 1; i >= 0; --i) {
    std::cout << v[i];
}
```

Цикл должен вывести `5 4 3 2 1` и остановиться. Но условие `i >= 0` для unsigned `i` всегда истинно! `i` уменьшается, на нуле она ещё валидная, на следующей итерации `--i` оборачивает в `4294967295`, и цикл продолжается. Программа залезает за границы вектора и крашится (или, хуже, выдаёт мусор).

С `int` такой проблемы нет:

```cpp
for (int i = v.size() - 1; i >= 0; --i) {
    std::cout << v[i];
}
```

Когда `i` станет -1, условие `>= 0` нарушится, цикл завершится.

Поэтому правило: **используйте `int` или `long` (signed) для индексов и счётчиков, даже если они логически не отрицательные**.

Когда оправдан unsigned:
- Битовые операции (`AND`, `OR`, `XOR`, сдвиги) — там знак не имеет смысла.
- Когда вам нужны именно полные 64 бита диапазона (signed long long даёт только 63).
- Когда вы реально хотите arithmetic mod 2^N (например, в хэширующих функциях).

### Целочисленные типы фиксированного размера

Раз размеры основных типов не зафиксированы, иногда надо именно «8 битов» или именно «32 бита». На этот случай в стандартной библиотеке есть типы из заголовочного файла `<cstdint>`:

```cpp
#include <cstdint>

int8_t   a = 1;   // ровно 1 байт со знаком (-128..127)
uint8_t  b = 1;   // ровно 1 байт без знака (0..255)
int16_t  c = 1;   // ровно 2 байта со знаком
uint16_t d = 1;   // ровно 2 байта без знака
int32_t  e = 1;   // ровно 4 байта со знаком
uint32_t f = 1;   // ровно 4 байта без знака
int64_t  g = 1;   // ровно 8 байт со знаком
uint64_t h = 1;   // ровно 8 байт без знака
```

Эти типы гарантированно одного размера на всех платформах. Удобно для бинарных форматов файлов и сетевых протоколов, где важна точная раскладка байтов.

Внутри это псевдонимы (`typedef` или `using`). На Linux/macOS `int32_t` — это обычно `int`. На Windows — тоже `int`. Но писать `int32_t` яснее: ты сразу видишь «здесь нужны ровно 4 байта».

В этой книге я буду стараться использовать `int` для обычных счётчиков (это коротко, и так все пишут), и `int32_t/uint64_t/etc` там, где размер важен (например, форматы файлов в проекте мини-СУБД).

### Литералы целых чисел

Когда вы пишете в коде число `42` — это **литерал**. Его тип по умолчанию — самый маленький из (`int`, `long`, `long long`), который вмещает значение. Для большинства чисел — `int`.

Можно явно указать тип литерала **суффиксом**:

```cpp
42        // int
42L       // long
42LL      // long long
42U       // unsigned int
42UL      // unsigned long
42ULL     // unsigned long long
```

Регистр суффикса роли не играет: `42ll`, `42LL`, `42lL` — всё одно. Но писать большими лучше — маленькая `l` визуально путается с цифрой `1`.

Кроме десятичной формы, литералы можно писать:

```cpp
42        // десятичный
0x2A      // шестнадцатеричный (0x префикс)
0b101010  // двоичный (0b префикс, появился в C++14)
052       // восьмеричный (один ноль в начале)
```

Все четыре записи — одно и то же число 42. Восьмеричной формой почти никто не пользуется — в практике она встречается только в правах доступа Unix (вспомните `chmod 755`).

С C++14 разрешены **разделители разрядов**:

```cpp
1'000'000      // миллион, читается легче чем 1000000
0xFF'FF        // 65535
0b1010'1100    // байт
```

Апостроф между цифрами — просто визуальное разделение, на значение не влияет. Очень удобно для длинных чисел. Но это C++14, и в нашей C++11-базе не сработает.

## Дробные числа: float и double

Для дробных чисел в C++ есть три типа:

```cpp
float       f = 3.14f;     // 4 байта
double      d = 3.14;      // 8 байт
long double ld = 3.14L;    // зависит — 8, 12 или 16
```

В прошлой главе про IEEE 754 я уже упоминал детали. Здесь повторю важное:

- `float` — 4 байта, **примерно 7 значащих десятичных цифр** точности. Диапазон: ±10⁻³⁸ … ±10³⁸.
- `double` — 8 байт, **примерно 15-16 значащих цифр**. Диапазон: ±10⁻³⁰⁸ … ±10³⁰⁸.
- `long double` — на x86-64 Linux обычно 80-битное число с заполнением до 16 байт. На macOS ARM64 — то же, что `double` (Apple не реализовала extended precision на ARM). На Windows — то же, что `double`.

Если коротко: **используйте `double`** для всех расчётов. Это разумный дефолт. `float` берите только когда у вас огромный массив чисел и память жмёт (4 vs 8 байт даст экономию вдвое), или когда работаете с библиотекой, которая ждёт именно `float` (GPU, OpenGL, аудио). `long double` — экзотика, не нужная в 99% задач.

### Литералы дробных чисел

```cpp
3.14         // double по умолчанию
3.14f        // float
3.14L        // long double
1.0          // double, потому что 1.0 это не целое
1e6          // 1 миллион, double (экспоненциальная форма)
1.5e-3       // 0.0015, double
1.5E-3       // то же — регистр не важен
```

`f`-суффикс для `float` обязателен, если вы хотите именно `float`. Если написать `float f = 3.14;` — компилятор предупредит «implicit conversion from double to float», потому что `3.14` без `f` — это `double`, и оно «теряет точность» при присвоении в `float`.

### Точность — самое больное место

Двоичная плавающая точка не может точно представить большинство десятичных дробей. Классический пример:

```cpp
#include <iostream>

int main() {
    double x = 0.1 + 0.2;
    std::cout << x << "\n";              // 0.3 — но это печать с округлением!
    std::cout.precision(20);
    std::cout << x << "\n";              // 0.30000000000000004441
    
    if (x == 0.3) std::cout << "equal\n";
    else          std::cout << "NOT equal\n";   // эта ветка!
    return 0;
}
```

`0.1 + 0.2` не равно ровно `0.3`. Поэтому **сравнивать дробные числа на равенство почти никогда нельзя**. Вместо `if (x == 0.3)` пишут:

```cpp
#include <cmath>

if (std::abs(x - 0.3) < 1e-9) {   // отличается меньше чем на 10⁻⁹
    // считаем равными
}
```

Или, для совсем серьёзных случаев, есть `std::numeric_limits<double>::epsilon()` — но это уже тема главы про библиотеку.

И ещё: **никогда не храните деньги в `double`**. Кажется логично — деньги это числа, что не так? А то, что у вас на счёте `100.10$`. Программа на сервере умножает баланс на процент: `100.10 * 1.05 = 105.105`. Округляете до двух знаков — `105.11`. Но на самом деле в `double` лежало не `100.10`, а `100.09999999999999`. Умножение даёт `105.10499999999999`. Округление — `105.10`. Копейка пропала. Бухгалтерия в шоке.

Для денег используйте либо `int64_t` в копейках/центах (баланс хранится как 10010 копеек), либо специальные библиотеки decimal-arithmetic. В нашей книге денег не будет, но имейте в виду на будущее.

## bool

Тип для логических значений:

```cpp
bool a = true;
bool b = false;
bool c = (5 > 3);   // c = true
```

Два значения — `true` и `false`. Размер `sizeof(bool)` обычно 1 байт (хотя нужен только 1 бит — но процессоры не умеют адресовать отдельные биты).

В C++ `bool` неявно конвертируется к `int`: `true` → 1, `false` → 0. И наоборот: любое ненулевое число → `true`, ноль → `false`.

```cpp
int n = 5;
if (n) {           // эквивалентно if (n != 0)
    std::cout << "non-zero\n";
}

bool b = 42;       // b = true, потому что 42 != 0
int x = true;      // x = 1
```

Эта возможность — приятное наследие C, но иногда мешает. Современный C++ пишет явно:

```cpp
if (n != 0) { ... }    // лучше, чем if (n)
if (ptr != nullptr) { ... }  // лучше, чем if (ptr)
```

В компиляторах есть флаги, ругающиеся на неявные конверсии (`-Wconversion`), и я их рекомендую включать на новых проектах.

## char и символы

`char` — целочисленный тип размером 1 байт, традиционно используемый для хранения одного символа ASCII.

```cpp
char c = 'A';
std::cout << c;        // напечатает A
std::cout << (int)c;   // напечатает 65 (код ASCII буквы A)
```

`'A'` — это литерал символа, **одинарные кавычки**, ровно один символ внутри. Его тип — `char`, значение — числовой код символа в ASCII (или Latin-1, или в чём угодно, что компилятор выбрал; для буквы A это всегда 65).

Двойные кавычки — это уже **строка**: `"A"` — это не `char`, а `const char[2]` (массив из двух элементов: `'A'` и невидимого `'\0'` в конце). Принципиально другой тип.

### Escape-последовательности

В символьном или строковом литерале нельзя написать буквальный перевод строки или кавычку. Для них используют escape-последовательности:

```cpp
'\n'    // перевод строки (newline)
'\t'    // табуляция
'\r'    // возврат каретки (на Windows используется в паре \r\n)
'\\'    // обратный слеш
'\''    // одинарная кавычка
'\"'    // двойная кавычка (внутри строкового литерала)
'\0'    // нулевой символ (терминатор C-строк)
'\xFF'  // байт со значением 0xFF (255)
'\377'  // байт со значением 0377 в восьмеричной (= 255)
```

### char, signed char, unsigned char

Один из неприятных уголков C++: тип `char` может быть как signed, так и unsigned — **зависит от компилятора и платформы**. На большинстве — signed (диапазон -128..127), но на ARM-Linux исторически unsigned (0..255).

В реальности это редко имеет значение для текста (ASCII только 0-127, попадает в обе интерпретации). Но если работаете с байтами как с числами:

```cpp
char c = 0xFF;
int n = c;       // 0xFF → -1 (если char signed) или 255 (если unsigned)
```

Чтобы было определённо, пишите явно:

```cpp
signed char sc = 0xFF;       // -1
unsigned char uc = 0xFF;     // 255
```

В большинстве случаев `char` для текста, `unsigned char` или `uint8_t` для байтов.

## const — переменная, которую нельзя менять

Иногда нужно сказать «вот значение, я его задаю один раз и потом не меняю». Это **константа**. В C++ ставится модификатор `const`:

```cpp
const int max_size = 100;
const double pi = 3.14159;

max_size = 200;   // ОШИБКА компиляции: assignment of read-only variable
```

`const`-переменная инициализируется при создании, и больше её значение менять нельзя. Попытка — ошибка компиляции.

Зачем это нужно?

- **Документация для читателя**. Видя `const int max_size`, читатель сразу понимает: это константа, она никогда не меняется.
- **Защита от случайных правок**. Если коллега полез в код и попытался изменить — компилятор остановит.
- **Возможности оптимизации**. Зная, что значение не меняется, компилятор может его «подставить» прямо в код, не читая из памяти.
- **Корректность функций**. Параметр функции, помеченный `const`, гарантирует: внутри функции его не меняют. Об этом подробно в главе 10.

Запомните железно: **в современном C++ всё, что не должно изменяться — должно быть `const`**. Это лучшая защита от багов.

## constexpr — константа времени компиляции (C++11)

`const` говорит «не менять». А `constexpr` (новинка C++11) говорит **«это значение известно на этапе компиляции»**.

```cpp
constexpr int max_size = 100;
constexpr double pi = 3.14159;
constexpr int doubled = max_size * 2;   // 200, посчитано на компиляции
```

Разница с `const`:

```cpp
int x;
std::cin >> x;
const int a = x;        // OK: a — константа, но её значение известно только в рантайме
constexpr int b = x;    // ОШИБКА: b должна быть известна на компиляции, а x — нет
constexpr int c = 100;  // OK: 100 — литерал, известен на компиляции
```

То есть `constexpr` строже, чем `const`: значение должно быть вычислимо компилятором.

Зачем? Для использования в местах, где нужно именно «значение компилятора». Например, размер массива:

```cpp
const int n = 10;
int array1[n];        // OK в C++ (хотя не в строгом стандарте)

int m;
std::cin >> m;
const int p = m;
int array2[p];        // НЕ OK: размер массива должен быть известен на компиляции
                      // (хотя GCC через VLA это разрешает как расширение)
```

`constexpr` решает эту проблему явно: «вот это точно вычислимо на компиляции, не сомневайся».

В C++14+ можно делать `constexpr`-функции, в C++20 — даже выделять память на куче на компиляции. Но в C++11 `constexpr` довольно ограничен — простые арифметические выражения с литералами и другими `constexpr`-переменными.

**Правило**: для констант предпочитайте `constexpr`. Если нельзя — `const`. Если хотите изменяемость — обычная переменная.

## Способы инициализации

В C++11 есть **три способа** проинициализировать переменную, и они немного отличаются. Это очень частый источник путаницы.

### Старый способ: с равно

```cpp
int x = 5;
double pi = 3.14;
char c = 'A';
```

Знакомый по другим языкам. Работает почти всегда.

### С круглыми скобками

```cpp
int x(5);
double pi(3.14);
char c('A');
```

Это «конструкторный синтаксис». Для встроенных типов делает то же, что `=`. Но для классов — вызывает соответствующий конструктор.

Подвох — **most vexing parse**:

```cpp
int x();   // НЕ объявление int x = 0! Это ОБЪЯВЛЕНИЕ ФУНКЦИИ x, возвращающей int
```

Компилятор интерпретирует `int x()` как объявление функции без параметров, возвращающей `int`. Из-за этой ловушки многие предпочитают другие синтаксисы.

### Единообразная инициализация (C++11): с фигурными скобками

```cpp
int x{5};
double pi{3.14};
char c{'A'};
```

Этот синтаксис **появился в C++11** и считается рекомендуемым. Преимущества:

1. **Работает везде одинаково**: для встроенных типов, классов, массивов, стандартных контейнеров.

   ```cpp
   int x{5};
   std::vector<int> v{1, 2, 3, 4};   // вектор из 4 элементов
   ```

2. **Защищает от «narrowing» — сужающих преобразований**. Если вы пытаетесь засунуть значение, которое не поместится — будет ошибка компиляции:

   ```cpp
   int x = 3.14;     // OK, x = 3 (молча отбросило 0.14)
   int y(3.14);      // OK, y = 3 (тоже молча)
   int z{3.14};      // ОШИБКА: narrowing conversion from double to int
   ```

   Эта проверка спасла моих коллег от десятков багов. Серьёзно.

3. **Не страдает от most vexing parse**:

   ```cpp
   int x{};   // x = 0 (value initialization), однозначно
   ```

В книге я буду использовать **`{}`** там, где это естественно, и `=` для простых случаев. Это слегка непоследовательно, но соответствует общепринятой практике.

### Default initialization vs value initialization

Что произойдёт, если объявить переменную **без значения**?

```cpp
int x;          // !!! не инициализирован
```

Для **локальной переменной встроенного типа** значение **не определено**. Внутри переменной — мусор, что было в памяти до этого. Чтение мусора — UB (undefined behavior).

```cpp
int x;
std::cout << x;   // UB — может напечатать что угодно, или упасть
```

Чтобы инициализировать нулём:

```cpp
int x{};         // x = 0, value initialization
int x = 0;       // тоже OK, но явно
```

Для **глобальных и static-переменных** правила другие: они **автоматически** инициализируются нулями (точнее — value initialization). Это потому, что глобалы лежат в `.bss`-секции, которая зануляется при загрузке (вспомните главу 7).

```cpp
int g;            // глобальная — автоматически 0
static int s;     // static — автоматически 0

int main() {
    int local;     // НЕ инициализирована
    std::cout << g << " " << s << " " << local;  // 0 0 ???
}
```

**Правило**: всегда инициализируйте локальные переменные. Не пишите `int x;` без значения. Привычка эта спасёт вас от сотен невоспроизводимых багов.

## auto — компилятор сам выводит тип (C++11)

В C++11 появилось ключевое слово `auto`. Оно говорит: «компилятор, сам определи тип из правой части».

```cpp
auto x = 5;         // компилятор видит 5 → int → x это int
auto y = 3.14;      // double
auto s = "hello";   // const char*
auto v = std::vector<int>{1, 2, 3};   // std::vector<int>
```

Зачем? Без `auto` иногда приходится писать длиннющие типы:

```cpp
std::map<std::string, std::vector<int>>::iterator it = m.begin();
```

С `auto`:

```cpp
auto it = m.begin();
```

Куда читабельнее.

### Когда auto хороший выбор

- Длинные типы (итераторы, типы из шаблонов).
- Когда тип очевиден из правой части:
  ```cpp
  auto x = std::vector<int>(100);   // ясно, что это vector<int>
  ```
- При работе с лямбдами (тип лямбды нельзя записать без `auto`).

### Когда auto плохой выбор

- Когда читатель не понимает, какой тип получится. Например:
  ```cpp
  auto x = some_func();   // что такое x?
  ```
  Если из имени функции не ясно — лучше написать тип явно.

- Когда `auto` скрывает важную деталь. Например:
  ```cpp
  for (auto x : container) { ... }
  ```
  Здесь `x` — копия! Если контейнер хранит большие объекты, копии дорогие.
  ```cpp
  for (const auto& x : container) { ... }
  ```
  А вот это — константная ссылка, без копирования. Гораздо лучше для больших объектов.

### auto и const/&

`auto` берёт тип «как есть», но **отбрасывает const и &**:

```cpp
const int& ref = ...;
auto a = ref;        // a — это int (без const, без &)
const auto& b = ref; // b — это const int& (как и ref)
```

Поэтому привычное `const auto&` — это «возьми тип, и сделай ссылкой на const». Самый частый паттерн для циклов:

```cpp
for (const auto& item : items) {
    // item — это const-ссылка на элемент контейнера
    // никаких копий, и нельзя случайно изменить
}
```

Запомните этот паттерн — он будет повторяться постоянно.

## Имена переменных: правила и стиль

Правила компилятора:
- Имя — буквы, цифры и подчёркивание.
- Начинаться с буквы или подчёркивания (но **не с цифры**).
- Регистр важен: `count` и `Count` — разные переменные.
- Нельзя использовать ключевые слова (`int`, `if`, `while`, и т. д.).
- Имена, начинающиеся с подчёркивания + заглавной буквы (`_Foo`) или с двух подчёркиваний (`__bar`), зарезервированы для компилятора и стандартной библиотеки. **Не используйте их.**
- В C++ разрешены **юникод-имена**:
  ```cpp
  int сумма = 0;   // работает (если компилятор настроен на UTF-8)
  ```
  Но я не рекомендую: смешение языков в коде раздражает, и не все системы понимают utf-8 source.

Стиль — это уже вопрос команды. Самые популярные:

- **snake_case** (`max_size`, `current_value`) — преобладает в стандартной библиотеке C++ и в стиле Google.
- **camelCase** (`maxSize`, `currentValue`) — преобладает в Java, popular в C++.
- **PascalCase** (`MaxSize`) — обычно для имён типов (классов, структур), не для переменных.

Я в книге использую **snake_case** для переменных, **PascalCase** для типов:

```cpp
int player_health;
double damage_multiplier;
class Player;
struct Inventory;
```

Это близко к стандартной библиотеке (`std::vector`, `std::string`) и читаемо.

Хорошие имена:
- Говорят, что переменная значит: `player_health`, `damage_per_round`, `is_alive`.
- Не сокращены до неузнаваемости: `cnt` плохо, `count` лучше, `enemy_count` ещё лучше.
- Не повторяют тип в имени: `int_count` плохо (и так видно по типу).
- Короткие имена — только для коротких циклов: `i`, `j`, `k` для счётчиков, `it` для итератора, `n` для размера.

Плохие имена:
- `temp`, `tmp`, `data`, `value` — не говорят ничего.
- `x1`, `x2`, `x3` — порядок появления, не смысл.
- `theBestVariableEverInTheWorld` — слишком длинное.

## Полный собранный пример

Соберём всё в работающую программу:

```cpp
#include <iostream>
#include <cstdint>

int main() {
    // Целочисленные типы
    int count = 42;
    long long big_number = 1000000000000LL;        // в C++14 для читаемости: 1'000'000'000'000LL
    unsigned int positive_only = 100;
    uint8_t one_byte = 255;
    
    // Дробные
    double pi = 3.14159265358979323846;
    float weight_kg = 75.5f;
    
    // Логический
    bool game_over = false;
    
    // Символ и строка (строки разберём в главе 12)
    char first_letter = 'A';
    const char* message = "Hello, C++!";
    
    // Константа времени компиляции
    constexpr int max_players = 8;
    
    // auto и инициализация фигурными скобками
    auto health = 100;        // int
    auto damage = 12.5;       // double
    auto enabled = true;      // bool
    
    int explicit_init{0};     // value initialization
    
    // Выводим (тут пока в одну строку, форматирование — в главе 12)
    std::cout << "count = " << count << "\n";
    std::cout << "big_number = " << big_number << "\n";
    std::cout << "pi = " << pi << "\n";
    std::cout << "weight_kg = " << weight_kg << "\n";
    std::cout << "game_over = " << game_over << "\n";
    std::cout << "first_letter = " << first_letter
              << " (code " << (int)first_letter << ")\n";
    std::cout << "max_players = " << max_players << "\n";
    
    return 0;
}
```

Сохраните как `types_demo.cpp`, соберите и запустите:

```bash
$ g++ -std=c++11 -Wall -Wextra types_demo.cpp -o types_demo
$ ./types_demo
```

Должно вывести что-то осмысленное. Если убрать `LL` у `big_number` — на 32-битных платформах будет переполнение и `-Wall` ругнётся.

## Преобразования типов: коротко

Между разными типами C++ умеет автоматически конвертировать. Правила:

```cpp
int i = 5;
double d = i;       // OK: int → double (расширение)

double pi = 3.14;
int j = pi;         // OK, но компилятор может предупредить — теряем 0.14

unsigned int u = 5;
int s = u;          // OK
unsigned int u2 = -1;   // ОЙ: -1 как unsigned = 4294967295. Предупреждение от -Wsign-conversion.

bool b = 1;         // OK: 1 → true
int n = false;      // OK: false → 0
```

Преобразования бывают:
- **Расширяющие** (widening): меньший тип → больший. Безопасно.
- **Сужающие** (narrowing): больший тип → меньший. Может терять данные.
- **Со знаком ↔ без знака**: интерпретация битов меняется, но биты те же. Опасно.

Через `{}` инициализацию (C++11) сужающие конверсии запрещены — это ошибка компиляции. Через `=` или `()` — только предупреждение, и то с подходящими флагами.

Явное преобразование пишут через `static_cast`:

```cpp
double pi = 3.14;
int n = static_cast<int>(pi);  // явно говорим: знаем что теряем дробную часть
```

Есть ещё `reinterpret_cast` (опасный, переинтерпретация битов) и `const_cast` (удаление const). К ним вернёмся в нужных местах книги.

## Главное — что увидите в коде дальше

Этой главы хватит, чтобы понимать почти любую переменную, которая будет встречаться. На примерах:

```cpp
int health = 100;                          // 4-байтное целое
double damage = 12.5;                      // 8-байтное дробное
bool alive = true;                         // логический
char first_letter = 'A';                   // 1-байтный символ
const int max_players = 8;                 // неизменяемая константа
constexpr double pi = 3.14159;             // константа времени компиляции
auto count = 42;                           // компилятор сам определит → int
auto it = container.begin();               // компилятор сам определит → итератор
const auto& item = container[0];           // const-ссылка, без копии
int32_t precise_size = 100;                // ровно 4 байта, для протоколов
uint8_t byte_value = 0xFF;                 // ровно 1 байт, для байтовых данных
```

К каждой из этих форм будете возвращаться постоянно.

## Маленькое упражнение

Соберите эти программы и проверьте, что вы правильно угадали поведение:

1. Узнайте размеры типов на вашем компьютере:
   ```cpp
   std::cout << sizeof(int) << " " << sizeof(long) << " " << sizeof(long long);
   ```
   На Linux/macOS x86-64 будет `4 8 8`. На Windows x86-64 — `4 4 8`.

2. Покажите, что unsigned оборачивается:
   ```cpp
   unsigned int x = 0;
   std::cout << x - 1 << "\n";  // напечатает 4294967295
   ```

3. Узнайте, signed или unsigned у вас `char`:
   ```cpp
   char c = -1;
   if (c < 0) std::cout << "char is signed\n";
   else       std::cout << "char is unsigned\n";
   ```

4. Покажите неточность плавающей точки:
   ```cpp
   std::cout.precision(20);
   double a = 0.1 + 0.2;
   std::cout << a;
   ```

5. (Самое полезное) Запустите программу с предупреждениями:
   ```cpp
   int main() {
       int x = 3.14;        // -Wfloat-conversion ругнётся
       int y{3.14};         // ошибка narrowing
       unsigned u = -1;     // -Wsign-conversion ругнётся
       int z;
       std::cout << z;      // -Wuninitialized ругнётся
       return 0;
   }
   ```
   Команда сборки: `g++ -std=c++11 -Wall -Wextra -Wpedantic -Wconversion test.cpp -o test`. Внимательно почитайте каждое предупреждение. Включите эти флаги во все проекты — они помогают.
