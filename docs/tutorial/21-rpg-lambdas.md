# Глава 21. Лямбды и std::function

В предыдущих главах мы уже много раз использовали лямбды, особо не вглядываясь. В `std::sort` с компаратором, в `std::count_if` с предикатом, в `Inventory::take` с предикатом поиска, в `EventBus<T>::subscribe` для обработчиков. Эта глава — детальный разбор: что такое лямбда под капотом, что значит каждый вид захвата, зачем `mutable`, что такое `std::function`, и где между ними разница.

Дополнительно построим `CommandRegistry` — реестр игровых команд, в котором имя команды отображается в обработчик-лямбду. Заменим длинную цепочку `if/else if` в `Game::execute` на короткий `commands_.dispatch(verb, rest)`.

## Лямбда — что это

**Лямбда** в C++ — это **анонимная функция**, объявленная прямо в коде, где она нужна.

```cpp
auto add = [](int a, int b) { return a + b; };
std::cout << add(3, 4);   // 7
```

`[](int a, int b) { return a + b; }` — это и есть лямбда. Расшифровка по частям:

- `[]` — **захват** (capture). Какие переменные снаружи лямбда «видит».
- `(int a, int b)` — параметры, как у обычной функции.
- `{ return a + b; }` — тело.
- (опционально) Между `()` и `{}` можно указать `-> int` — возвращаемый тип. Если опущен — компилятор выводит сам.

Тип лямбды компилятор генерирует автоматически. Программисту имя этого типа неизвестно. Поэтому используем `auto` или `std::function` для хранения.

```cpp
auto plus = [](int a, int b) { return a + b; };       // auto — самое короткое
std::function<int(int, int)> plus2 = ...;             // через std::function
```

## Анатомия захвата

Самая сложная часть. Захват — что лямбда **«запоминает»** из окружающего кода.

```cpp
int x = 10;
auto f = [x]() { return x + 1; };   // x захвачен по значению
std::cout << f();    // 11

x = 100;
std::cout << f();    // всё ещё 11! Лямбда хранит свою копию x
```

Возможные варианты:

### `[]` — без захвата

Лямбда не видит ничего из окружения. Только параметры и глобалы.

```cpp
auto inc = [](int x) { return x + 1; };
```

Самые «свободные» лямбды — могут конвертироваться в указатель на функцию, удобны как параметры в C-API.

### `[x]` — захват по значению

Делает **копию** переменной `x` в момент создания лямбды. Изменения `x` снаружи не влияют.

```cpp
int counter = 0;
auto f = [counter]() { return counter; };
counter = 100;
std::cout << f();   // 0 — захватили старое значение
```

Внутри лямбды захваченные по значению переменные **`const`** по умолчанию — изменять нельзя:

```cpp
int n = 5;
auto f = [n]() { n = 10; };   // ОШИБКА
```

Чтобы разрешить менять — `mutable`:

```cpp
auto f = [n]() mutable { n = 10; std::cout << n; };
f();
```

Но изменение влияет только на копию внутри лямбды. Снаружи `n` не меняется.

### `[&x]` — захват по ссылке

Лямбда «помнит» **ссылку** на `x`. Все изменения снаружи видны внутри, и наоборот.

```cpp
int counter = 0;
auto f = [&counter]() { counter++; };
f();
f();
f();
std::cout << counter;   // 3
```

Это часто используется для накопления состояния.

**Опасность**: ссылка живёт, пока лямбда живёт. Если лямбда переживёт `counter` — будет висячая ссылка → UB.

```cpp
std::function<void()> bad() {
    int x = 5;
    return [&x]() { std::cout << x; };   // !!! x уничтожится, ссылка висячая
}
```

Запоминайте: **захват по ссылке только когда лямбда живёт меньше, чем источник**. Часто это локальные функции и алгоритмы STL — там безопасно.

### `[=]` — захват **всего** по значению

Все переменные, которые лямбда использует, копируются.

```cpp
int x = 10, y = 20;
auto f = [=]() { return x + y; };   // x и y скопированы
```

Удобно, но опасно — можно случайно «прихватить» что-то лишнее. В современных стилях `[=]` часто не рекомендуют. Лучше явно указать, что захватываете.

### `[&]` — захват **всего** по ссылке

Все используемые переменные — по ссылке.

```cpp
int x, y, z;
auto f = [&]() { x = 1; y = 2; z = 3; };
```

Удобно для писателей в окружение. Та же опасность с висячими ссылками.

### `[this]` — захват указателя на текущий объект

Внутри методов класса можно захватить `this`:

```cpp
class Game {
public:
    void register_commands() {
        commands_.add("look", [this](const std::string&) {
            cmd_look();   // вызов метода этого Game
        });
    }
};
```

`[this]` копирует **указатель** `this`. Через него лямбда может вызывать методы и обращаться к полям.

Опасность: если `Game` уничтожится, а лямбда останется — `this` будет висячим. У нас `Game` живёт всё время программы, проблем нет.

В C++17 появился `[*this]` — копирует **сам объект**. В C++11 нет.

### `[x, &y]` — комбинированный

Можно смешивать:

```cpp
int x, y;
auto f = [x, &y]() { ... };   // x по значению, y по ссылке
```

### `[x = ...]` — захват с инициализатором (C++14)

```cpp
auto f = [n = 10]() { return n; };
```

В C++11 нет. У нас не появится.

## Что лямбда на самом деле

Лямбда — это **синтаксический сахар** для создания **функтора** (объекта-функции). Компилятор за вас генерирует класс примерно такого вида:

```cpp
int x = 10;
auto f = [x](int y) { return x + y; };

// эквивалент:
class __lambda_42 {
    int x;
public:
    __lambda_42(int x_) : x(x_) {}
    int operator()(int y) const { return x + y; }
};

auto f = __lambda_42(x);
```

То есть лямбда — это объект некоторого анонимного класса с **`operator()`**. Захват — это поля класса. Параметры — параметры `operator()`. Тело — тело `operator()`.

`mutable` лямбда — это объект без `const` на `operator()`:

```cpp
auto f = [n=10]() mutable { ++n; return n; };

// эквивалент:
class __lambda_42 {
    int n = 10;
public:
    int operator()() { return ++n; }   // нет const
};
```

Это помогает понять любую лямбду: «это безымянный объект, вызываемый через `()`».

## Производительность

Лямбды **дешёвые**. Они:
- Не выделяют память на куче (объект на стеке).
- Не используют виртуальные вызовы (вызов `operator()` инлайнится компилятором).
- Без захватов превращаются в указатель на функцию.

В STL-алгоритмах (`std::sort`, `std::find_if`) использование лямбды vs обычной функции в скорости **не отличается**. Иногда даже быстрее — потому что компилятор видит код лямбды на месте и инлайнит.

## std::function — type erasure

Лямбды все разного типа. Даже две одинаково выглядящие лямбды — два разных типа. Это создаёт проблему: как **хранить** лямбду в поле класса, если её тип не назвать?

`auto` работает только для **локальных** переменных. В классе как поле — нельзя.

Решение — **`std::function<Signature>`**. Это **type-erased** контейнер для любой callable.

```cpp
#include <functional>

std::function<int(int, int)> op = [](int a, int b) { return a + b; };
std::cout << op(3, 4);   // 7

op = [](int a, int b) { return a * b; };
std::cout << op(3, 4);   // 12

op = std::plus<int>();   // функтор тоже OK
std::cout << op(3, 4);   // 7

int my_func(int a, int b) { return a - b; }
op = my_func;            // указатель на функцию тоже OK
```

`std::function<int(int, int)>` принимает **любой** callable с сигнатурой «принимает (int, int), возвращает int». Лямбды, функторы, указатели на функции — всё подходит.

### Цена type erasure

`std::function` не бесплатный:

1. **Размер**: обычно 32-64 байта (внутри SBO — small buffer optimization, как у `std::string`).
2. **Аллокация для больших захватов**: если лямбда с захватом большего чем SBO размера, `std::function` выделит память на куче.
3. **Косвенный вызов**: внутри `std::function` хранится указатель на «виртуальную таблицу». Каждый вызов — это разыменование + вызов через указатель.

В критичных к производительности местах (горячий цикл, миллион вызовов) `std::function` чувствуется. В обычном коде (как наш `EventBus` или `CommandRegistry`) — не проблема.

### Когда использовать что

- **Шаблонный параметр** — самый дешёвый, без type erasure. Подходит, когда тип лямбды известен на компиляции:
  ```cpp
  template <typename F>
  void run(F f) { f(); }
  ```

- **`std::function`** — когда нужно **хранить** callable без знания его типа: поле класса, элемент в `vector`, возврат из функции с разными возможными лямбдами.

- **Указатель на функцию** — для C-API. Работает только без захватов.

В нашем `EventBus<T>` мы использовали `std::function<void(const Event&)>` — потому что нужно хранить разные обработчики в `vector`. Это типичный случай.

## Лямбды как параметры функций

Два способа принять лямбду:

```cpp
// 1. Шаблонный параметр — компилятор инлайнит, быстро
template <typename F>
void apply(F f) { f(); }

// 2. std::function — type-erased, проще читается
void apply(std::function<void()> f) { f(); }
```

STL использует первый подход — алгоритмы шаблонные.

Если функция большая и часто использует callback — `std::function` упрощает интерфейс. Если функция маленькая и часто вызывается — шаблон даёт лучшую производительность.

## std::bind — старый стиль (для контекста)

До лямбд для «частичного применения» функции использовали `std::bind`:

```cpp
#include <functional>

int sub(int a, int b) { return a - b; }

auto from_10 = std::bind(sub, 10, std::placeholders::_1);
std::cout << from_10(3);   // 10 - 3 = 7
```

Сложный синтаксис, ограничения, странные placeholders. В современном C++ это **полностью заменяется лямбдами**:

```cpp
auto from_10 = [](int x) { return sub(10, x); };
```

Лямбды короче, читаемее, эффективнее. `std::bind` в новом коде не пишите — но в старом увидите.

## NPC и поведения — намёк на будущее

Главу можно назвать «поведения NPC через лямбды», и вот пример, к чему мы потом придём:

```cpp
class NPC {
public:
    using Tick = std::function<void(NPC&, Game&)>;
    
    void on_tick(Tick t) { tick_ = std::move(t); }
    void update(Game& g) { if (tick_) tick_(*this, g); }
    
private:
    Tick tick_;
};

// Использование: NPC, который патрулирует туда-сюда
auto patroller = std::make_shared<NPC>();
patroller->on_tick([direction = 1](NPC& self, Game& g) mutable {
    // ходим вперёд-назад, переключая direction
    // ...
});
```

Каждый NPC имеет свой `tick`-обработчик. Один — патрулирует, другой — отвечает на приветствие, третий — продаёт товары. Все через лямбды с захватом своего состояния.

В нашей текущей RPG NPC ещё нет (добавятся за пределами книги, как упражнение). Но шаблон поведения вы уже понимаете.

## CommandRegistry — лямбды на работе

Главная интеграция этой главы. У нас в `Game::execute` была длинная цепочка:

```cpp
if (verb == "help") {
    cmd_help();
} else if (verb == "look" || verb == "l") {
    cmd_look();
} else if (verb == "go") {
    std::string dir; ss >> dir;
    if (dir.empty()) std::cout << "Куда идти?\n";
    else cmd_go(dir);
}
// ...ещё восемь веток...
else {
    std::cout << "Неизвестная команда\n";
}
```

Уродливо, длинно, и для каждой новой команды нужно добавлять `else if`. Перепишем через **словарь имя → лямбда**.

`include/commands.h`:

```cpp
class CommandRegistry {
public:
    using Handler = std::function<void(const std::string&)>;
    
    void add(const std::string& name, Handler handler);
    void add_alias(const std::string& alias, const std::string& target);
    bool dispatch(const std::string& verb, const std::string& rest) const;
    std::vector<std::string> names() const;

private:
    std::unordered_map<std::string, Handler> handlers_;
    std::unordered_map<std::string, std::string> aliases_;
};
```

Реализация — простая:

```cpp
bool CommandRegistry::dispatch(const std::string& verb, const std::string& rest) const {
    std::string resolved = verb;
    auto alias_it = aliases_.find(verb);
    if (alias_it != aliases_.end()) {
        resolved = alias_it->second;
    }
    
    auto it = handlers_.find(resolved);
    if (it == handlers_.end()) return false;
    
    it->second(rest);
    return true;
}
```

Сначала разрешаем алиас (`l` → `look`), потом ищем обработчик, потом вызываем с аргументом.

### Регистрация команд

В `Game::register_commands()`:

```cpp
void Game::register_commands() {
    commands_.add("help",       [this](const std::string&) { cmd_help(); });
    commands_.add("look",       [this](const std::string&) { cmd_look(); });
    commands_.add("status",     [this](const std::string&) { cmd_status(); });
    commands_.add("inventory",  [this](const std::string&) { cmd_inventory(); });
    commands_.add("go",         [this](const std::string& rest) {
        if (rest.empty()) std::cout << "Куда идти?\n";
        else cmd_go(rest);
    });
    commands_.add("take",       [this](const std::string& rest) {
        if (rest.empty()) std::cout << "Что взять?\n";
        else cmd_take(rest);
    });
    commands_.add("drop",       [this](const std::string& rest) { /* ... */ });
    commands_.add("use",        [this](const std::string& rest) { /* ... */ });
    commands_.add("quit",       [this](const std::string&) { running_ = false; });

    commands_.add_alias("l",   "look");
    commands_.add_alias("i",   "inventory");
    commands_.add_alias("inv", "inventory");
    commands_.add_alias("stat","status");
    commands_.add_alias("get", "take");
    commands_.add_alias("q",   "quit");
    commands_.add_alias("exit","quit");
}
```

Каждая команда — лямбда с захватом `this`. `[this]` копирует указатель, через него лямбда вызывает метод `cmd_xxx`. `CommandRegistry` ничего о `Game` не знает — он просто хранит обработчики.

В сигнатуре `Handler = std::function<void(const std::string&)>` — обработчик принимает «остаток строки» (всё после verb). Это позволяет вытащить аргумент:

```cpp
// Ввод: "go east"
// verb = "go", rest = "east"
```

### Парсинг

В `Game::step()`:

```cpp
std::istringstream ss(line);
std::string verb;
ss >> verb;

std::string rest;
std::getline(ss, rest);
rest = trim_left(rest);

if (!commands_.dispatch(verb, rest)) {
    std::cout << "Неизвестная команда: '" << verb << "'.\n";
}
```

Извлекаем первое слово как `verb`, остальное как `rest` (через `getline` после `>>` забирает остаток строки), убираем ведущие пробелы. Вся логика — в `CommandRegistry`.

### help автоматический

```cpp
void Game::cmd_help() const {
    std::cout << "Команды:\n";
    for (const auto& name : commands_.names()) {
        std::cout << "  " << name << "\n";
    }
}
```

`commands_.names()` возвращает список всех зарегистрированных. Help автоматически показывает что есть. Добавите новую команду — она появится в help без правок.

### Что выиграли

- Цепочка `if/else` исчезла.
- Новая команда — одна строка `commands_.add(...)`.
- Алиасы централизованы.
- Help автогенерируется.
- Парсер изолирован от логики команд.

Это **стандартный паттерн** организации команд в REPL/CLI программах: словарь обработчиков плюс единая точка диспетчеризации. В нашей mini-shell (часть III) сделаем то же самое.

## Главные правила главы

1. **Лямбда — это объект анонимного класса с `operator()`.** Не магия.
2. **Захват `[var]` копирует, `[&var]` ссылка.** Запоминайте опасность висячих ссылок.
3. **`mutable`** для изменения захваченных по значению.
4. **`[this]`** для лямбд в методах класса.
5. **`auto` для хранения лямбды**, `std::function<Signature>` для типостёртого хранения в полях/контейнерах.
6. **`std::function` не бесплатен** — стоимость аллокации для больших захватов и косвенного вызова.
7. **Шаблонный параметр** для callback в шаблонных функциях — быстрее, чем `std::function`.
8. **`std::bind` устарел** — заменяйте лямбдами.
