# Глава 12. Строки и потоки ввода-вывода

Программы редко обходятся без текста. Прочитать имя пользователя, вывести список товаров, открыть файл с настройками, разобрать команду «attack goblin» — всё это строки. В этой главе разберём, как с ними работать в C++.

C++ — язык с историей. Поэтому строки тут двух видов: **C-style** (наследие C, `char*` с нулевым байтом в конце) и **C++-style** (`std::string`, RAII-обёртка с современным интерфейсом). Я расскажу про обе, но писать в реальном коде будем `std::string`. Глава 11 уже дала нужный фундамент: `std::string` — это просто RAII-объект, который владеет куском памяти на куче.

## Старая школа: C-strings

В C, до появления `std::string`, строкой назывался **массив `char` с нулевым байтом в конце**:

```c
char str[] = "Hello";
// в памяти: 'H' 'e' 'l' 'l' 'o' '\0'
// размер: 6 байт (5 видимых + терминатор)
```

Терминатор `'\0'` нужен, чтобы все функции знали, где строка кончается. `strlen("Hello")` пробегает по символам до первого нуля и возвращает 5. Нет терминатора — выйдет за границы массива в чужую память, UB.

В C++ литералы `"Hello"` имеют тип `const char[6]` (массив из 6 элементов), который легко конвертируется в `const char*` (указатель на первый символ):

```cpp
const char* msg = "Hello";
std::cout << msg << "\n";   // OK
std::cout << msg[1] << "\n"; // 'e'
```

C-строки до сих пор используются:
- В системных API (`open(const char*, ...)`, `printf(const char*, ...)`).
- В литералах в коде — `"Hello"` это C-строка, и компилятор её хранит в `.rodata`.
- В производительности — иногда нужно избежать аллокации `std::string`.

Но писать **новый** код на C-строках почти никогда не стоит. Слишком много ловушек:

- **Нельзя просто склеить.** `"hello" + " world"` в C — UB (это сложение двух указателей).
- **Размер не известен из типа.** `char[]` теряет размер при передаче в функцию (там это уже `char*`).
- **Терминатор легко забыть.** Все функции типа `strcat`, `strcpy` пишут в чужую память, если буфер маловат.

Поэтому весь современный C++-код использует `std::string`. C-строку оставляем для интерфейса с C-API.

## std::string — основа основ

`std::string` — это объект, который **владеет** куском памяти с текстом. Управляет им через RAII: выделяет в конструкторе, освобождает в деструкторе. Никаких ручных `delete`. Можно копировать, передавать в функции, возвращать — всё работает корректно.

Подключается через заголовок `<string>`:

```cpp
#include <string>
```

(Обычно подтянется автоматически через `<iostream>`, но лучше явно.)

### Создание и базовые операции

```cpp
std::string a;                  // пустая строка
std::string b = "Hello";        // из C-строки
std::string c("World");          // через конструктор
std::string d{"!"};              // uniform initialization
std::string e(5, 'x');           // "xxxxx" — 5 одинаковых символов
std::string f = b;               // копия b

// Размер
std::cout << b.size() << "\n";   // 5
std::cout << b.length() << "\n"; // 5 (синоним size)
std::cout << b.empty() << "\n";  // 0 (false)
std::cout << a.empty() << "\n";  // 1 (true)
```

`size()` возвращает количество **байтов**. Для ASCII совпадает с количеством символов. Для UTF-8 — нет (русская буква занимает 2 байта; мы говорили в главе 2).

### Конкатенация

Главная сила `std::string` — её можно склеивать оператором `+`:

```cpp
std::string first = "Hello";
std::string second = "World";
std::string greeting = first + ", " + second + "!";   // "Hello, World!"
```

И дописывать в существующую через `+=`:

```cpp
std::string s = "Hello";
s += ", ";       // "Hello, "
s += "World";    // "Hello, World"
s += '!';        // "Hello, World!"  (даже одиночный char можно добавить)
```

Под капотом конкатенация — это **аллокация новой памяти, копирование старой строки, копирование добавляемой части, освобождение старой**. Не бесплатная операция, но обычно достаточно быстрая.

Если строите длинную строку через много `+=`, `std::string` иногда выделяет больше, чем нужно, чтобы следующие `+=` не вызывали аллокацию. Это похоже на `std::vector`. Для критичной производительности можно явно зарезервировать через `s.reserve(1000)` — выделить место под 1000 символов сразу.

### Индексация и обход

```cpp
std::string s = "Hello";
char c = s[0];           // 'H'
s[0] = 'J';              // s теперь "Jello"

// Обход через range-based for (C++11)
for (char ch : s) {
    std::cout << ch << "\n";
}

// Обход с индексами
for (size_t i = 0; i < s.size(); ++i) {
    std::cout << i << ": " << s[i] << "\n";
}
```

`s[i]` **не проверяет границы**. `s[100]` на 5-символьной строке — UB. Если нужна проверка с исключением — `s.at(i)`:

```cpp
try {
    char c = s.at(100);     // выкинет std::out_of_range
} catch (const std::out_of_range& e) {
    std::cout << "out of range\n";
}
```

В цикле проверки замедлили бы код, поэтому почти всегда используют `[]`, а правильность границ обеспечивают сами.

### Сравнение

```cpp
std::string a = "apple";
std::string b = "banana";
std::string c = "apple";

if (a == c) ...     // true
if (a != b) ...     // true
if (a < b) ...      // true (лексикографически по байтам)
```

`==`, `!=`, `<`, `>`, `<=`, `>=` работают как ожидаешь — сравнение байт за байтом. Регистр учитывается, заглавные < строчных (по таблице ASCII).

В C-стиле сравнивать через `==` нельзя:

```cpp
const char* a = "apple";
const char* b = "apple";
if (a == b) ...       // ОШИБКА в смысле: сравниваются указатели, не содержимое!
```

Это сравнение указателей. Чтобы сравнить содержимое, нужен `strcmp(a, b) == 0`. Ещё один повод использовать `std::string`.

### Подстроки

```cpp
std::string s = "Hello, World!";

std::string sub = s.substr(7, 5);     // "World" — с позиции 7, длиной 5
std::string sub2 = s.substr(7);        // "World!" — с позиции 7 до конца
```

### Поиск

```cpp
std::string s = "Hello, World, World!";

size_t pos = s.find("World");           // 7 — позиция первого вхождения
size_t pos2 = s.find("World", 8);       // 14 — поиск с позиции 8

if (s.find("Foo") == std::string::npos) {
    std::cout << "не найдено\n";
}
```

`std::string::npos` — специальное значение (обычно максимум `size_t`), возвращаемое при «не найдено». Запомните проверку `== npos`.

### Замена и вставка

```cpp
std::string s = "Hello, World!";
s.replace(7, 5, "C++");                // Hello, C++!
s.insert(0, "Greetings: ");             // Greetings: Hello, C++!
s.erase(0, 11);                         // Hello, C++!
```

Не особенно частая операция, но иногда нужна.

### Преобразование к C-строке

Когда нужно передать в C-API, который ждёт `const char*`:

```cpp
std::string s = "test.txt";
FILE* f = std::fopen(s.c_str(), "r");
```

`s.c_str()` возвращает `const char*` на содержимое строки, с гарантированным `'\0'` на конце. Указатель **валиден, пока строка не изменена** — после `s += "x"` он может стать невалидным. Не сохраняйте `c_str()` надолго.

### Преобразования с числами

```cpp
#include <string>

// Число → строка
std::string s1 = std::to_string(42);          // "42"
std::string s2 = std::to_string(3.14);         // "3.140000" (увы, форматирование куцее)

// Строка → число
int n = std::stoi("42");          // 42
double d = std::stod("3.14");      // 3.14
long ll = std::stoll("1234567890"); // 1234567890

// Если строка не парсится — выкинет исключение
try {
    int bad = std::stoi("not a number");
} catch (const std::invalid_argument& e) {
    std::cout << "не число\n";
}
```

`std::to_string` для дробных даёт «6 цифр после точки» — не всегда хорошо. Для приличного форматирования используют `std::stringstream` (об этом ниже).

### Что лежит внутри std::string

Под капотом `std::string` обычно содержит три поля:
- Указатель на буфер с символами (на куче).
- Текущая длина.
- Текущая ёмкость (capacity) — сколько символов помещается без новой аллокации.

То есть это **указатель + два размера** ≈ 24 байта на 64-битной системе. Сама строка лежит отдельно, в куче.

Современные реализации хорошо оптимизированы: для **коротких** строк (~15 символов на GCC libstdc++, ~22 на clang libc++) данные хранятся **внутри** самой `std::string`, без аллокации. Это называется **SSO** — Small String Optimization. Поэтому `std::string s = "hi"` обычно вообще не выделяет память на куче. А `std::string s = "очень длинная строка..."` — выделит.

### Итог по строкам

- Используйте `std::string` везде.
- C-строки — только для интерфейса с C-API.
- `s.size()` — количество **байтов**, не символов (для UTF-8 будут отличаться).
- `s[i]` без проверки, `s.at(i)` с исключением.
- `==`, `<` сравнивают содержимое, а не указатели.
- Поиск через `find`, проверка `== npos`.
- `c_str()` — для передачи в C-API; не сохранять надолго.
- `to_string`, `stoi`, `stod` — конверсии с числами.

## std::cout — вывод

С `std::cout` мы знакомы с главы 6. Здесь — детали.

`std::cout` — это объект класса `std::ostream`. Оператор `<<` — это **сдвиг влево**, но для потоков перегружен как «вставить в поток». Возвращает сам поток, поэтому можно цеплять:

```cpp
std::cout << "Имя: " << name << ", возраст: " << age << "\n";
```

Это эквивалентно:

```cpp
((((std::cout << "Имя: ") << name) << ", возраст: ") << age) << "\n";
```

Каждый `<<` принимает поток и значение, кладёт значение в поток, возвращает поток.

`<<` поддерживает все встроенные типы плюс `std::string`, `const char*`. Для своих типов перегрузку можно написать самому — об этом в главе 16.

### endl против `\n`

Что лучше:

```cpp
std::cout << "Hello" << std::endl;
std::cout << "Hello\n";
```

Оба выводят «Hello» с переводом строки. Разница:
- `std::endl` дополнительно **сбрасывает буфер** — заставляет немедленно записать содержимое в терминал/файл.
- `"\n"` — просто символ перевода строки, ничего не сбрасывает.

Когда программа выводит много, флушинг каждой строки — заметная трата. Для производительности предпочитайте `"\n"`. `std::endl` оставляйте для случаев, когда нужно немедленно показать пользователю (например, прогресс).

Современный код часто пишет `"\n"` везде, и я тоже буду так.

### std::cerr — поток ошибок

`std::cerr` — отдельный поток для ошибок. По умолчанию связан с тем же терминалом, что и `std::cout`, но **не буферизирован**. Каждая запись сразу выводится.

```cpp
std::cerr << "Error: cannot open file\n";
```

Зачем разделять? В Unix-философии:
- `std::cout` — основной вывод, его можно перенаправить (`./program > result.txt`).
- `std::cerr` — диагностика, она остаётся в терминале (даже после перенаправления).

```bash
$ ./program > out.txt
Error: cannot open file       # это std::cerr — на экране
$ cat out.txt
обычные выводы программы      # это std::cout — в файле
```

Это полезно: пользователь видит ошибки сразу, даже если стандартный вывод куда-то перенаправлен.

`std::clog` — ещё один поток ошибок, **буферизированный**. Используется редко.

### Форматирование вывода

По умолчанию числа выводятся «как есть»:

```cpp
std::cout << 3.14159265 << "\n";   // 3.14159
std::cout << 1234567 << "\n";       // 1234567
std::cout << true << "\n";          // 1
```

Чтобы управлять форматом — манипуляторы из `<iomanip>`:

```cpp
#include <iomanip>

// Число знаков после запятой:
std::cout << std::fixed << std::setprecision(2) << 3.14159 << "\n";   // 3.14

// Ширина поля (выравнивание):
std::cout << std::setw(10) << 42 << "\n";       // "        42" — справа
std::cout << std::left << std::setw(10) << 42 << "|\n"; // "42        |" — слева

// Заполнитель:
std::cout << std::setfill('0') << std::setw(4) << 42 << "\n";  // "0042"

// Системы счисления:
std::cout << std::hex << 255 << "\n";    // ff
std::cout << std::oct << 8 << "\n";      // 10
std::cout << std::dec << 255 << "\n";    // 255 (десятичная — стандартная)

// Логические как true/false:
std::cout << std::boolalpha << true << "\n";    // true
std::cout << std::noboolalpha << true << "\n";  // 1
```

Большинство манипуляторов **остаются в силе** на следующие выводы — это «состояние потока». Если установили `std::hex` — все числа дальше будут в hex до явного `std::dec`. Это иногда подвох. Принято возвращать поток в дефолт после нестандартного формата.

Чёткое управление шириной полей — для красивых таблиц:

```cpp
std::cout << std::left
          << std::setw(15) << "Name"
          << std::setw(5) << "Age"
          << "\n";

for (const auto& person : people) {
    std::cout << std::left
              << std::setw(15) << person.name
              << std::setw(5) << person.age
              << "\n";
}
```

Получится:

```
Name           Age  
Alice          30   
Bob            25   
Charlie        42   
```

В современном C++20 появилась `std::format` (как Python f-strings), но в C++11 её нет.

## std::cin — ввод

`std::cin` — стандартный ввод. По умолчанию читает с клавиатуры.

```cpp
int age;
std::cout << "Сколько вам лет? ";
std::cin >> age;
std::cout << "Вы ввели " << age << "\n";
```

Оператор `>>` («извлечь из потока»):
- Пропускает ведущие пробелы и переводы строк.
- Читает до первого пробела/перевода строки.
- Преобразует прочитанное в нужный тип.

Если ввели нечто, что не парсится как `int` — поток переходит в **failure state**, переменная остаётся неинициализированной (или со старым значением). После `cin >> age` хорошо проверить:

```cpp
int age;
if (std::cin >> age) {
    std::cout << "OK, возраст " << age << "\n";
} else {
    std::cout << "Не число\n";
    std::cin.clear();   // сбросить failure
    std::cin.ignore(1000, '\n');  // пропустить плохие символы до конца строки
}
```

Эта проверка работает потому, что `std::cin >> age` возвращает сам поток, который в булевом контексте даёт `true` если всё ОК, `false` если ошибка.

### Несколько значений подряд

```cpp
int a, b, c;
std::cin >> a >> b >> c;     // три числа, разделённых пробелами или переводами строк
```

Если ввести «3 5 7» и Enter — `a=3, b=5, c=7`. Так же сработает «`3\n5\n7`» — пробельные символы любые.

### Чтение строки целиком: getline

`std::cin >> s` для строки прочитает до первого пробела. Если хочется прочитать **всю строку** (включая пробелы):

```cpp
std::string name;
std::getline(std::cin, name);
```

`getline` читает до перевода строки (не включая) и сохраняет в `name`. Идеально для имён, фраз, путей.

### Главная ловушка cin: смешивание >> и getline

Самый частый баг новичка в I/O. Код такой:

```cpp
int age;
std::string name;

std::cin >> age;                 // вводят 25 + Enter
std::getline(std::cin, name);    // вводят "John"

std::cout << age << " " << name;
```

Ожидаешь: `25 John`. На самом деле: `25 ` (имя пустое!).

Почему? Когда вы вводите `25 Enter`, в буфере остаётся `25\n`. `cin >> age` читает `25` и **оставляет `\n`** в буфере. Дальше `getline` сразу видит `\n` — и считает строку пустой.

Решение — после `>>` явно пропустить остаток строки:

```cpp
std::cin >> age;
std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
std::getline(std::cin, name);
```

`std::cin.ignore(N, ch)` пропускает до N символов или до встречи `ch`. С большим N (max) — пропустит до конца строки.

Громоздко, но необходимо. Альтернатива — **всегда** читать через `getline` и парсить руками:

```cpp
std::string line;
std::getline(std::cin, line);
int age = std::stoi(line);

std::string name;
std::getline(std::cin, name);
```

Этот стиль безопаснее. В книге я буду чередовать в зависимости от ситуации.

## Файловые потоки

Файлы открываются через `std::ifstream` (для чтения) и `std::ofstream` (для записи). Обе — RAII-обёртки, как мы видели в главе 11.

### Чтение из файла

```cpp
#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::ifstream file("data.txt");
    if (!file.is_open()) {
        std::cerr << "Не удалось открыть файл\n";
        return 1;
    }
    
    std::string line;
    while (std::getline(file, line)) {
        std::cout << line << "\n";
    }
    
    return 0;
    // файл закроется автоматически в деструкторе
}
```

Проверка `if (!file.is_open())` — открыть могли не удать (нет файла, нет прав). `while (std::getline(file, line))` — стандартный паттерн чтения построчно: цикл продолжается, пока `getline` успешно читает; на конце файла `getline` ставит failure state, цикл завершается.

Также можно читать через `>>` — числа, отдельные слова:

```cpp
std::ifstream file("numbers.txt");
int n;
while (file >> n) {
    std::cout << n * 2 << "\n";
}
```

### Запись в файл

```cpp
#include <fstream>

int main() {
    std::ofstream file("output.txt");
    if (!file.is_open()) {
        return 1;
    }
    
    file << "Hello, file!\n";
    file << "Number: " << 42 << "\n";
    
    return 0;
}
```

По умолчанию `std::ofstream` открывает файл **на перезапись**: если он был — содержимое затирается. Чтобы дописать в конец:

```cpp
std::ofstream file("log.txt", std::ios::app);
file << "новая запись\n";
```

`std::ios::app` — флаг «append». Файл открывается так, что каждая запись добавляется в конец.

Другие флаги:
- `std::ios::in` — для чтения (`ifstream` по умолчанию это и делает).
- `std::ios::out` — для записи (`ofstream` по умолчанию).
- `std::ios::app` — append.
- `std::ios::ate` — открыть и сразу перейти в конец (для записи или чтения).
- `std::ios::binary` — бинарный режим. По умолчанию текстовый — на Windows `\n` превращается в `\r\n` при записи. Бинарный — без преобразований.
- `std::ios::trunc` — очистить файл при открытии (по умолчанию для `ofstream`).

Флаги можно комбинировать через `|`:

```cpp
std::ofstream file("data.bin", std::ios::out | std::ios::binary);
```

### Бинарные данные

Когда нужно записать «сырые» байты:

```cpp
int values[] = {1, 2, 3, 4, 5};
std::ofstream out("data.bin", std::ios::binary);
out.write(reinterpret_cast<const char*>(values), sizeof(values));
```

`write(const char*, size_t)` пишет заданное количество байтов. `reinterpret_cast<const char*>` — это говорит компилятору «трактуй этот указатель как `const char*`». Об этом ужасе в проекте мини-СУБД (глава 32).

Аналогично `read`:

```cpp
int loaded[5];
std::ifstream in("data.bin", std::ios::binary);
in.read(reinterpret_cast<char*>(loaded), sizeof(loaded));
```

### Полностью прочитать файл

Иногда хочется прочитать весь файл в строку:

```cpp
#include <fstream>
#include <sstream>
#include <string>

std::string read_file(const std::string& filename) {
    std::ifstream in(filename);
    if (!in.is_open()) return "";
    
    std::stringstream buffer;
    buffer << in.rdbuf();
    return buffer.str();
}
```

`in.rdbuf()` — это «внутренний буфер» потока. Перенаправляя его в `stringstream`, мы копируем всё содержимое. Дальше `buffer.str()` возвращает результат.

## std::stringstream — строка как поток

Иногда нужны возможности потока для работы со строками. Например, разобрать строку в числа:

```cpp
#include <sstream>

std::string line = "1 2 3 4 5";
std::stringstream ss(line);

int n;
while (ss >> n) {
    std::cout << n * 2 << "\n";
}
```

`std::stringstream` — поток, работающий с памятью, а не с файлом. Поддерживает `<<` и `>>`. Полезно для:
- Разбора строк (как пример выше).
- Сборки строк с форматированием.

### Форматированная сборка строк

`std::to_string` для дробных мало настраивается. С `stringstream` точнее:

```cpp
#include <sstream>
#include <iomanip>

std::stringstream ss;
ss << std::fixed << std::setprecision(2) << 3.14159;
std::string s = ss.str();    // "3.14"
```

Это идиома, которую вы будете использовать постоянно для красивого форматирования.

Класс отдельно для записи — `std::ostringstream`. Для чтения — `std::istringstream`. `std::stringstream` — оба сразу.

## Сводный пример: разобрать CSV

Соберём осмысленный пример. Файл `people.csv`:

```
Alice,30,Engineer
Bob,25,Designer
Charlie,42,Manager
```

Прочитаем его и выведем красивой таблицей:

```cpp
#include <iostream>
#include <fstream>
#include <sstream>
#include <string>
#include <vector>
#include <iomanip>

struct Person {
    std::string name;
    int age;
    std::string job;
};

std::vector<Person> read_csv(const std::string& filename) {
    std::vector<Person> people;
    std::ifstream file(filename);
    if (!file.is_open()) {
        std::cerr << "Не могу открыть " << filename << "\n";
        return people;
    }
    
    std::string line;
    while (std::getline(file, line)) {
        std::stringstream ss(line);
        Person p;
        
        std::getline(ss, p.name, ',');
        
        std::string age_str;
        std::getline(ss, age_str, ',');
        p.age = std::stoi(age_str);
        
        std::getline(ss, p.job);
        
        people.push_back(p);
    }
    
    return people;
}

void print_table(const std::vector<Person>& people) {
    std::cout << std::left
              << std::setw(15) << "Name"
              << std::setw(5)  << "Age"
              << "Job\n";
    std::cout << std::string(30, '-') << "\n";
    
    for (const auto& p : people) {
        std::cout << std::left
                  << std::setw(15) << p.name
                  << std::setw(5)  << p.age
                  << p.job << "\n";
    }
}

int main() {
    auto people = read_csv("people.csv");
    print_table(people);
    return 0;
}
```

Создайте файл `people.csv` с указанным содержимым, соберите программу:

```bash
$ g++ -std=c++11 -Wall -Wextra csv.cpp -o csv
$ ./csv
Name           Age  Job
------------------------------
Alice          30   Engineer
Bob            25   Designer
Charlie        42   Manager
```

Что использовано:
- `std::ifstream` для чтения файла.
- `std::getline` с **разделителем** (третий параметр) — читает до указанного символа.
- `std::stringstream` для разбора одной строки на поля.
- `std::stoi` для конвертации строки в число.
- Форматирование таблицы через `std::setw` и `std::left`.
- Заполнение разделителя через `std::string(30, '-')` (30 минусов).

## Пара тонкостей

### Чтение чисел и точка в качестве разделителя

Если у вас файл с дробными числами в локали с **запятой** в качестве разделителя (русская локаль):

```
3,14
2,71
```

Стандартный `>>` на дробное число ждёт **точку**. Поэтому он прочитает `3` и остановится. Чтобы поток понимал запятую — нужно настроить локаль:

```cpp
std::cin.imbue(std::locale("ru_RU.UTF-8"));
```

В книжных примерах я везде использую точку. На реальных проектах с локалями отдельно разбираться.

### Юникод и std::string

Что будет если прочитать русский текст?

```cpp
std::string s;
std::cin >> s;   // вводим "Привет"
std::cout << s;  // печатается "Привет"
```

Работает! `std::string` хранит байты, и поток ввода/вывода тоже работает с байтами. Никаких преобразований. Если терминал на UTF-8 (на современных macOS/Linux так), всё проходит через без потерь.

**Но**: `s.size()` будет 12 байтов (русские буквы по 2 в UTF-8), не 6 символов. И `s[0]` будет первым байтом многобайтного символа, не первой буквой. Для правильной работы с символами нужно конвертировать в `std::u32string` (UTF-32) или использовать библиотеку типа ICU. В нашей книге обходимся байтами — для большинства задач достаточно.

### sync_with_stdio

В C из тех же файлов можно писать через `printf/scanf`. По умолчанию C++ потоки **синхронизируются** с C-потоками, чтобы можно было смешивать `printf` и `std::cout`. Это замедляет ввод-вывод.

Если в вашей программе только C++-потоки и нужно ускорить (актуально для соревновательного программирования):

```cpp
std::ios::sync_with_stdio(false);
std::cin.tie(nullptr);
```

В обычных проектах не нужно.

## Главные правила главы

1. **Всегда `std::string`, не C-строки.** Исключение — только при работе с C-API.
2. **`"\n"` вместо `std::endl`** для скорости.
3. **`std::cerr` для ошибок, `std::cout` для основного вывода.** Не смешивайте.
4. **После `cin >> x` пропускайте остаток строки**, если потом `getline`.
5. **Проверяйте, что файл открылся** через `is_open()`.
6. **Файловые потоки сами закрываются** в деструкторе — не нужен явный `close()`, можно и не нужно.
7. **`std::stringstream` — мощная штука** для парсинга и форматирования.
