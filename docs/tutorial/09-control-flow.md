# Глава 9. Управляющие конструкции

В главе 4 мы обсуждали ветвление и циклы концептуально, на псевдокоде. В главе 8 разобрались с переменными. Теперь склеиваем — пишем настоящие управляющие конструкции на C++. Тут много синтаксиса, но материал в целом простой: после Python/PHP/JS большая часть будет узнаваемой. Главное — пара ловушек, на которых спотыкаются новички, и одна-две особенности C++, которых нет в других языках.

## if — простое ветвление

Базовая форма:

```cpp
if (условие) {
    действия;
}
```

Если `условие` истинно — выполняются действия в `{...}`. Иначе — пропускаются.

```cpp
int health = 50;
if (health < 30) {
    std::cout << "Внимание: мало HP!\n";
}
```

Скобки `(...)` вокруг условия — **обязательны**. В отличие от Python или Ruby, в C++ нельзя написать `if health < 30 {...}`.

Фигурные скобки `{...}` вокруг тела — формально необязательны, если внутри одно действие:

```cpp
if (health < 30)
    std::cout << "Мало HP!\n";
```

Но я **настоятельно рекомендую всегда писать `{...}`**. Без скобок легко вляпаться:

```cpp
if (health < 30)
    health = health + 10;
    std::cout << "Heal!\n";   // эта строка выполнится ВСЕГДА!
```

Отступы вводят в заблуждение. Без `{...}` к `if` относится только первая строка, второй `std::cout` выполняется всегда. Внутрь `if` он не входит, потому что нет фигурных скобок. Я лично потерял несколько часов на таких багах в начале карьеры. С скобками такой ошибки не сделать:

```cpp
if (health < 30) {
    health = health + 10;
    std::cout << "Heal!\n";
}
```

Дешёвый страховочный полис. Не экономьте две строки.

## if/else

Альтернативная ветка пишется через `else`:

```cpp
if (health > 0) {
    std::cout << "Жив\n";
} else {
    std::cout << "Мёртв\n";
}
```

`else if` для нескольких условий подряд:

```cpp
if (health <= 0) {
    std::cout << "Мёртв\n";
} else if (health < 30) {
    std::cout << "Тяжёлое ранение\n";
} else if (health < 70) {
    std::cout << "Ранен\n";
} else {
    std::cout << "В порядке\n";
}
```

Проверки идут **сверху вниз**. Срабатывает первая истинная. Остальные не проверяются — важно, если в условиях есть вычисления.

Кстати, `else if` в C++ — это не отдельная конструкция, а просто `else` со вложенным `if`. То есть код выше эквивалентен:

```cpp
if (health <= 0) {
    ...
} else {
    if (health < 30) {
        ...
    } else {
        if (...) { ... }
    }
}
```

Но первая форма читается лучше, поэтому все так и пишут.

## Логические операции в условиях

Условие — это любое выражение, которое можно интерпретировать как `bool`. Самые частые операции:

```cpp
==    // равно
!=    // не равно
<     // меньше
<=    // меньше или равно
>     // больше
>=    // больше или равно
&&    // логическое И
||    // логическое ИЛИ
!     // логическое НЕ
```

Примеры:

```cpp
if (age >= 18 && age < 65) {
    std::cout << "Работоспособный возраст\n";
}

if (day == "суббота" || day == "воскресенье") {
    std::cout << "Выходной\n";
}

if (!alive) {
    std::cout << "Не жив\n";   // эквивалентно alive == false
}
```

### Ловушка номер один: `=` vs `==`

Это самый частый баг новичка в C++ (и в C, и в Java, и в JS).

`=` — это **присваивание**. `x = 5` — положить 5 в переменную x.

`==` — это **сравнение**. `x == 5` — проверить, равен ли x пятёрке.

В условии нужно сравнение. Если случайно написать одно равно:

```cpp
if (health = 0) {     // ОЙ!
    ...
}
```

— то компилятор не выдаст ошибку. Он подумает: «Ага, программист хочет положить 0 в health, а потом проверить, что присвоено». В присваивании результат — само значение, то есть `0`. Ноль интерпретируется как `false`. Условие никогда не сработает. И ещё в `health` уляглись 0 — побочный эффект.

Очень коварный баг. Современные компиляторы это ловят:

```bash
warning: using the result of an assignment as a condition without parentheses
```

— но только с флагами `-Wall`. Включайте флаги.

Есть приём защиты — **сравнение задом наперёд**, когда константа слева:

```cpp
if (0 == health) {   // если случайно один знак — ошибка компиляции
    ...
}
```

Если написать `0 = health` — ошибка: нельзя присваивать константе. Но эта запись неестественная (читается «если ноль равен health» — задом наперёд). В современном C++ за неё не голосуют. Просто будьте внимательны и используйте флаги.

### Short-circuit evaluation

Очень важная особенность: операторы `&&` и `||` **сокращают вычисления**.

Для `A && B`: если `A` ложно — `B` **не вычисляется**. Результат всё равно ложь.

Для `A || B`: если `A` истинно — `B` не вычисляется. Результат всё равно истина.

Зачем это полезно? Защита от ошибок:

```cpp
if (ptr != nullptr && ptr->value > 0) {
    ...
}
```

Здесь, если `ptr` нулевой — мы **не** обращаемся к `ptr->value` (что было бы UB и крашем программы). Сначала проверили, что ptr не пуст, и только потом разыменовали.

То же самое с делением:

```cpp
if (b != 0 && a / b > 5) {
    ...
}
```

Деление на ноль не произойдёт, потому что `b != 0` ложь → `a / b` не вычисляется.

Помните этот порядок — он спасает кучу багов.

### Скобки и приоритет

Когда операторов несколько, могут возникать вопросы порядка:

```cpp
if (a == 5 || b == 5 && c == 5) {
    ...
}
```

Что тут? `(a == 5) || ((b == 5) && (c == 5))`? Или `((a == 5) || (b == 5)) && (c == 5)`?

В C++ `&&` имеет **приоритет выше** `||`. То есть `&&` «связывает крепче». Расшифровка — первая.

Я **очень рекомендую** писать скобки явно:

```cpp
if ((a == 5) || (b == 5 && c == 5)) {
    ...
}
```

Скобки лишние? Лучше лишние, чем непонятные. Особенно когда условие сложное.

## Дополнительный конструкт: if с инициализацией (C++17)

С C++17 можно объявлять переменную прямо в условии:

```cpp
if (int x = compute(); x > 0) {
    use(x);
}
// x здесь уже не виден
```

Это C++17, и в нашей C++11-базе **не работает**. Но удобная штука, упоминаю на будущее.

В C++11 эквивалент:

```cpp
{
    int x = compute();
    if (x > 0) {
        use(x);
    }
}
// x здесь не виден
```

## Тернарный оператор

Краткая форма if/else для простого выбора между двумя значениями:

```cpp
условие ? значение_если_истина : значение_если_ложь
```

Пример:

```cpp
int abs_value = (x < 0) ? -x : x;
```

Эквивалент:

```cpp
int abs_value;
if (x < 0) {
    abs_value = -x;
} else {
    abs_value = x;
}
```

Тернарник полезен в выражениях, где хочется выбрать значение:

```cpp
std::cout << "Урон: " << (is_critical ? damage * 2 : damage) << "\n";
```

С тернарником без `( )` вокруг — может быть некрасиво:

```cpp
int x = a > b ? a : b;   // максимум, читается ок
```

Но злоупотреблять не стоит. Когда условие сложное или выбираемых значений много — лучше обычный `if/else`. Тернарник без скобок легко спутать с другими операторами:

```cpp
int y = x > 0 ? 1 : x < 0 ? -1 : 0;   // SIGNUM, но читать тяжело
```

Лучше переписать в `if/else if/else` — будет понятнее.

## switch — выбор из множества значений

Когда у вас много альтернатив на одну и ту же переменную:

```cpp
char direction;
std::cin >> direction;

switch (direction) {
    case 'N':
        std::cout << "Идёшь на север\n";
        break;
    case 'S':
        std::cout << "Идёшь на юг\n";
        break;
    case 'E':
        std::cout << "Идёшь на восток\n";
        break;
    case 'W':
        std::cout << "Идёшь на запад\n";
        break;
    default:
        std::cout << "Неизвестное направление\n";
        break;
}
```

Эквивалент через `if/else if`:

```cpp
if (direction == 'N') {
    ...
} else if (direction == 'S') {
    ...
} else if (...) {
    ...
} else {
    ...
}
```

`switch` — другая форма того же. Когда вариантов много и все они проверяют одну переменную — `switch` обычно читается лучше. Плюс, компилятор иногда генерирует **более быстрый код** через таблицу переходов (jump table) вместо последовательных проверок. Не всегда — это оптимизация, и её делает компилятор по своему усмотрению.

### Ограничения switch

В `switch` можно проверять **только целочисленные и перечислимые** типы (`int`, `char`, `enum`, и т. д.). **Нельзя** — `double`, `std::string`, объекты классов. Поэтому такое **не сработает**:

```cpp
std::string cmd;
std::cin >> cmd;

switch (cmd) {                       // ОШИБКА компиляции
    case "look": ...
    case "take": ...
}
```

Для строк используют `if/else if`.

Сами `case`-значения должны быть **constexpr-выражениями**:

```cpp
const int MAX = 10;
constexpr int MIN = 1;

switch (x) {
    case MAX: ...   // OK, MAX это const int с известным значением
    case MIN: ...   // OK, constexpr
    case y:   ...   // ОШИБКА, y не известно на компиляции
}
```

### Fall-through — главная ловушка switch

Заметили `break` после каждого `case`? Если его убрать — выполнение **«просачивается» вниз** к следующему case. Это называется fall-through, и оно унаследовано из C.

```cpp
switch (x) {
    case 1:
        std::cout << "one ";
        // нет break — ВНИМАНИЕ
    case 2:
        std::cout << "two ";
        break;
    case 3:
        std::cout << "three ";
        break;
}
```

При `x == 1` напечатается `one two `! Потому что после `case 1` нет `break`, выполнение продолжается в `case 2`.

Чаще всего fall-through — это **баг** (программист забыл `break`). Иногда — фича, когда несколько `case` должны делать одно:

```cpp
switch (cmd) {
    case 'h':
    case 'H':
    case '?':
        show_help();
        break;
    case 'q':
    case 'Q':
        quit();
        break;
}
```

Здесь fall-through сознательный — обрабатываем верхний и нижний регистр одной веткой. В C++17 для явности добавили атрибут `[[fallthrough]]`:

```cpp
case 1:
    do_one();
    [[fallthrough]];   // явно говорим: «знаю что нет break, это специально»
case 2:
    do_two();
    break;
```

В C++11 такого нет — обходимся комментарием `// fall-through`. Современные компиляторы могут выдавать предупреждение про fall-through (`-Wimplicit-fallthrough`), и принимают комментарии в качестве «глушилки».

### default

`default` — что делать, если ни один `case` не подошёл. Опционально, но **очень полезно**. Если все случаи перечислены — поставьте `default` с сообщением об ошибке или `assert`:

```cpp
switch (state) {
    case State::Idle:   ...; break;
    case State::Active: ...; break;
    case State::Done:   ...; break;
    default:
        std::cerr << "Unknown state\n";
        std::abort();
}
```

Так, если в будущем добавите `State::Error`, но забудете `case` — программа упадёт с понятной ошибкой, а не «странно поведёт себя». Современные компиляторы с `-Wswitch` ругаются, если для `enum` пропущен `case`.

## while — цикл с проверкой в начале

```cpp
while (условие) {
    действия;
}
```

Сначала проверяется условие. Если истинно — выполняются действия, потом снова проверка, и так далее. Когда условие становится ложным — выход.

Если условие изначально ложно — тело не выполнится ни разу.

```cpp
int health = 100;
while (health > 0) {
    health = health - 10;
    std::cout << "HP: " << health << "\n";
}
std::cout << "Игрок умер\n";
```

Циклы — главный источник багов. Самые частые проблемы:

**Бесконечный цикл.** Условие никогда не становится ложным. Например:

```cpp
int i = 0;
while (i < 10) {
    std::cout << i << "\n";
    // забыли увеличить i — цикл вечный
}
```

Программа печатает `0 0 0 0 ...` бесконечно. Прервите через Ctrl+C.

**Off-by-one error** (ошибка на единицу). Цикл выполняется на один раз больше или меньше, чем надо. Классика — `<` vs `<=`:

```cpp
for (int i = 0; i < 10; ++i) {    // 10 итераций: i = 0, 1, ..., 9
    ...
}
for (int i = 0; i <= 10; ++i) {   // 11 итераций: i = 0, 1, ..., 10
    ...
}
```

Программисты привыкли к первой форме (`< n`), потому что она даёт ровно `n` итераций и в индексной нотации совпадает с длиной массива.

**Изменение неправильной переменной.** Особенно во вложенных циклах:

```cpp
int i = 0;
while (i < 10) {
    int j = 0;
    while (j < 5) {
        std::cout << i << "," << j;
        i = i + 1;   // ОЙ! Меняем i во внутреннем цикле
        j = j + 1;
    }
}
```

Внешний цикл сходит с ума, потому что `i` меняется внутри. Часто такие баги — результат копи-пасты.

### Бесконечный цикл нарочно

Иногда хочется именно вечный цикл (внутри будет `break` по какому-то условию):

```cpp
while (true) {
    auto cmd = read_command();
    if (cmd == "quit") break;
    execute(cmd);
}
```

Это идиома REPL (read-eval-print loop). Сервер тоже обычно крутится в `while (true)`.

Эквивалентная запись — `for (;;)`:

```cpp
for (;;) {
    ...
}
```

Это тот же бесконечный цикл, just другой синтаксис. Используется реже, но встречается в чужом коде.

## do-while — цикл с проверкой в конце

```cpp
do {
    действия;
} while (условие);
```

В отличие от `while`, тело выполняется **минимум один раз** — сначала действие, потом проверка.

```cpp
int answer;
do {
    std::cout << "Введите число 1-10: ";
    std::cin >> answer;
} while (answer < 1 || answer > 10);
```

Программа просит ввести число, пока не введут что-то в диапазоне. Сначала всегда спрашивает, потом проверяет.

Точка с запятой **после** `while (...)` обязательна — `do-while` это особая конструкция.

`do-while` нужен редко. Большинство случаев лучше переписываются в обычный `while`. Я в своей практике пишу его, может быть, раз в год — когда хочется именно «выполнить и проверить».

## for — классический цикл

Самая частая форма цикла в C/C++:

```cpp
for (инициализация; условие; шаг) {
    действия;
}
```

Эквивалент через `while`:

```cpp
инициализация;
while (условие) {
    действия;
    шаг;
}
```

Классический пример — перебор от 0 до N-1:

```cpp
for (int i = 0; i < 10; ++i) {
    std::cout << i << "\n";
}
```

Разбор по частям:
- **`int i = 0`** — выполняется один раз, перед циклом.
- **`i < 10`** — проверяется перед каждой итерацией. Если истина — выполняется тело.
- **`++i`** — выполняется после каждой итерации тела. Увеличивает `i` на 1.

`++i` — это **инкремент**, увеличение на 1. Чуть короче и быстрее, чем `i = i + 1` (для встроенных типов разницы практически нет, для итераторов класса — лучше `++i`).

Есть ещё `i++` — постфиксный инкремент. На встроенных типах в условии цикла **разницы нет**. Но в общем случае:
- `++i` — увеличить и вернуть **новое** значение.
- `i++` — запомнить старое значение, увеличить, вернуть **старое**.

Префиксный `++i` для итераторов классов чуть быстрее (не делает копию), поэтому в for-циклах я пишу `++i`. Это вошло в привычку у всего C++-сообщества.

### Все три части — опциональны

Можно опустить любую часть:

```cpp
int i = 0;
for (; i < 10; ++i) {        // инициализации нет
    ...
}

for (int i = 0; ; ++i) {     // условия нет — бесконечный цикл
    if (...) break;
    ...
}

for (int i = 0; i < 10;) {   // шага нет — должен меняться внутри
    ...
    i = i + 2;
}

for (;;) {                    // вечный цикл
    ...
}
```

Чаще всего я пишу классическую полную форму. Опускания — редкая экзотика.

### Несколько переменных в for

В части инициализации можно объявить несколько переменных:

```cpp
for (int i = 0, j = 10; i < j; ++i, --j) {
    std::cout << i << " " << j << "\n";
}
```

Печатает `0 10`, `1 9`, `2 8`, `3 7`, `4 6`. Останавливается, когда `i` догоняет `j`.

В шаге запятая — это **оператор запятая**, выполняющий несколько выражений по очереди. Используется редко, но иногда удобно для одновременного движения двух переменных.

## Range-based for — главная новинка C++11

Классический `for` хорош, но если нужно просто пройтись по всем элементам контейнера — много букв. В C++11 добавили краткую форму:

```cpp
std::vector<int> v = {10, 20, 30, 40, 50};

for (int x : v) {
    std::cout << x << "\n";
}
```

Читается «для каждого `x` из `v`». Без индексов, без счётчиков. Эквивалент классического:

```cpp
for (size_t i = 0; i < v.size(); ++i) {
    int x = v[i];
    std::cout << x << "\n";
}
```

Range-based for работает для любого, у кого есть `begin()` и `end()` (методы или функции). Это все стандартные контейнеры (`vector`, `array`, `map`, `set`, `string`), а также массивы:

```cpp
int arr[] = {1, 2, 3, 4, 5};
for (int x : arr) {
    std::cout << x << "\n";
}
```

### По ссылке vs по значению

В записи `for (int x : v)` `x` — это **копия** элемента. Менять `x` бесполезно — оригинал не изменится:

```cpp
std::vector<int> v = {1, 2, 3};
for (int x : v) {
    x = x * 2;   // меняет копию, не оригинал
}
// v всё ещё {1, 2, 3}
```

Чтобы менять оригинал — берём по ссылке (`&`):

```cpp
for (int& x : v) {
    x = x * 2;
}
// v теперь {2, 4, 6}
```

Если контейнер хранит большие объекты (`std::string`, классы), копировать дорого — берите хотя бы константную ссылку:

```cpp
std::vector<std::string> names = {"Alice", "Bob", "Charlie"};

// Плохо: каждый name копируется (стоит выделения памяти и копирования содержимого)
for (std::string name : names) {
    std::cout << name << "\n";
}

// Хорошо: константная ссылка, без копий
for (const std::string& name : names) {
    std::cout << name << "\n";
}
```

С `auto` запись становится ещё короче:

```cpp
for (const auto& name : names) {
    std::cout << name << "\n";
}
```

Это идиома, которую вы будете писать постоянно. Запоминайте: **`for (const auto& x : container)`**.

### Если нужен индекс — классический for

Range-based for не даёт индекс. Если он нужен (например, чтобы напечатать «элемент номер 3»):

```cpp
for (size_t i = 0; i < v.size(); ++i) {
    std::cout << i << ": " << v[i] << "\n";
}
```

(`size_t` — стандартный беззнаковый тип для размеров и индексов; обычно эквивалент `unsigned long`. Можно использовать `int`, но `-Wsign-compare` тогда ругнётся; см. главу 8 — лучше signed для индексов всё-таки, но `size_t` — общепринятая практика для итерирования.)

В C++20 появилось `std::views::enumerate`, дающее одновременно индекс и значение. До тех пор — классический for с индексом.

## break и continue

`break` — **выход** из ближайшего цикла или `switch`. Мы видели его в `switch`. В цикле:

```cpp
for (int i = 0; i < 100; ++i) {
    if (found_what_we_want(i)) {
        break;   // выходим из цикла
    }
}
```

`continue` — **переход к следующей итерации** того же цикла. Текущая итерация прерывается:

```cpp
for (int i = 0; i < 10; ++i) {
    if (i % 2 == 0) {
        continue;   // пропускаем чётные
    }
    std::cout << i << "\n";   // печатает только нечётные
}
```

Что важно: `break` и `continue` влияют **только на ближайший цикл**. Если их вызвать из вложенного цикла — выйдут только из внутреннего:

```cpp
for (int i = 0; i < 10; ++i) {
    for (int j = 0; j < 10; ++j) {
        if (found) {
            break;   // выходит ТОЛЬКО из внутреннего for
        }
    }
    // сюда попадаем после break — продолжается внешний цикл
}
```

Это иногда раздражает — хочется выйти сразу из двух циклов. Варианты решения:

**1. Флаг:**
```cpp
bool done = false;
for (int i = 0; i < 10 && !done; ++i) {
    for (int j = 0; j < 10; ++j) {
        if (found) {
            done = true;
            break;
        }
    }
}
```

Работает, но проверка `&& !done` каждую итерацию — некрасиво.

**2. Выделить в функцию + return:**
```cpp
auto search = []() -> std::pair<int,int> {
    for (int i = 0; i < 10; ++i) {
        for (int j = 0; j < 10; ++j) {
            if (found) return {i, j};
        }
    }
    return {-1, -1};
};
```

Иногда самый чистый вариант. Лямбды разберём в главе 21.

**3. goto.** Серьёзно. Об этом ниже.

## goto — реабилитация чёрной овцы

В каждой книге по программированию пишут «никогда не используйте goto». Это идёт из эссе Дейкстры 1968 года «Goto Considered Harmful». Эссе было верным **в контексте того времени** — программы на ассемблере и Fortran с goto превращались в спагетти, в которых ничего нельзя было понять.

В современном структурированном коде у `goto` остались два-три **законных** применения, и я о них расскажу.

Синтаксис `goto` простой:

```cpp
goto метка;
...
метка:
    действие;
```

`goto` перепрыгивает на строку с меткой. Всё. Прыгать можно только внутри одной функции, нельзя пересекать инициализации переменных (компилятор не разрешит).

**Применение 1: выход из вложенных циклов.**

```cpp
for (int i = 0; i < 10; ++i) {
    for (int j = 0; j < 10; ++j) {
        if (found) goto done;
    }
}
done:
    std::cout << "Found at " << i << "," << j << "\n";
```

Чисто и без лишних флагов. В C++ этот паттерн считается приемлемым.

**Применение 2: освобождение ресурсов на ошибке (C-стиль).**

```c
int* a = malloc(...);
int* b = malloc(...);
int* c = malloc(...);

if (something_failed) {
    goto cleanup;
}

// ... использование ...

cleanup:
    free(c);
    free(b);
    free(a);
```

В C это типичный паттерн «единственная точка очистки». В **C++** для этого есть **гораздо лучшие средства** — RAII (мы разберём в главе 11), деструкторы, smart pointers. Поэтому в C++ этот паттерн почти не нужен. Но если читаете старый C-код или общаетесь с C-API — будете видеть.

**Что нельзя делать с goto:**

- Прыгать вперёд через инициализацию переменной (компилятор не даст).
- Прыгать в другую функцию (только внутри одной).
- Использовать как «удобный if» — `if (...) goto err;` в обычном потоке. Это создаёт путаницу.

В нашей книге `goto` встретится максимум один-два раза — в местах, где он реально лучше альтернатив.

## Циклы с итераторами (предварительно)

В C++ есть концепция **итераторов** — обобщённого способа перебирать элементы. Это основа STL. Подробно — в главе 14, но для полноты картины упомяну:

```cpp
std::vector<int> v = {10, 20, 30};

for (auto it = v.begin(); it != v.end(); ++it) {
    std::cout << *it << "\n";   // *it — это значение по итератору
}
```

`v.begin()` — итератор на первый элемент. `v.end()` — итератор «за последний» (sentinel). `++it` — перейти к следующему. `*it` — получить значение.

В C++11 такой цикл превращается в краткий range-based for, и писать его руками не надо. Но иногда классический for-с-итератором нужен — например, когда хочется иметь итератор для модификации контейнера прямо во время прохода. К этому вернёмся.

## Что выучить про управляющие конструкции

| Конструкция | Когда брать |
|-------------|-------------|
| `if/else` | Простое ветвление, 1-3 ветки. |
| `else if`-цепочка | Несколько альтернатив. Если их много и они на одну переменную — рассмотрите `switch`. |
| Тернарник `?:` | В выражениях, выбор простого значения. Не больше одного на строку. |
| `switch` | Много веток на одну целочисленную/`enum` переменную. Не забывайте `break`! |
| `while` | Цикл с предусловием. Когда количество итераций неизвестно. |
| `do-while` | Цикл с пост-условием. Когда нужно гарантировать хотя бы один проход. |
| `for` (классический) | Цикл с известным числом итераций (от и до). Когда нужен индекс. |
| Range-based `for` | Перебор всех элементов контейнера. Самый частый цикл в C++11+. |
| `break` | Выйти из ближайшего цикла или `switch`. |
| `continue` | Перейти к следующей итерации. |
| `goto` | Выход из вложенных циклов. В редких случаях. |

## Пара рекомендаций

1. **Всегда фигурные скобки `{...}` после if/else/for/while**, даже если тело — одна строка.
2. **Всегда `break` в case** (или явный `[[fallthrough]]`/комментарий).
3. **default в switch** — даже если думаете, что не нужен. Будущие изменения добавят варианты.
4. **Range-based for с `const auto&`** для перебора. Запомните идиому.
5. **Включите флаги** `-Wall -Wextra -Wpedantic` — компилятор найдёт половину ловушек этой главы.

## Пример: «угадай число»

Соберём что-то живое из всего изученного. Простая игра: компьютер загадывает число от 1 до 100, игрок угадывает. Программа подсказывает «больше» или «меньше».

```cpp
#include <iostream>
#include <cstdlib>   // для rand и srand
#include <ctime>     // для time

int main() {
    // Инициализируем генератор случайных чисел текущим временем
    std::srand(static_cast<unsigned>(std::time(nullptr)));
    
    constexpr int min_value = 1;
    constexpr int max_value = 100;
    constexpr int max_attempts = 10;
    
    int target = std::rand() % (max_value - min_value + 1) + min_value;
    
    std::cout << "Угадай число от " << min_value << " до " << max_value << "\n";
    std::cout << "У тебя " << max_attempts << " попыток.\n";
    
    bool won = false;
    
    for (int attempt = 1; attempt <= max_attempts; ++attempt) {
        std::cout << "\nПопытка " << attempt << "/" << max_attempts << ": ";
        
        int guess;
        std::cin >> guess;
        
        if (guess < min_value || guess > max_value) {
            std::cout << "Число вне диапазона. Попробуй ещё.\n";
            continue;
        }
        
        if (guess == target) {
            std::cout << "Угадал! Это " << target << ".\n";
            won = true;
            break;
        } else if (guess < target) {
            std::cout << "Загаданное больше.\n";
        } else {
            std::cout << "Загаданное меньше.\n";
        }
    }
    
    if (!won) {
        std::cout << "\nПопытки кончились. Это было " << target << ".\n";
    }
    
    return 0;
}
```

Соберите:

```bash
$ g++ -std=c++11 -Wall -Wextra guess.cpp -o guess
$ ./guess
```

Что тут использовано:
- `constexpr` для констант (глава 8).
- `static_cast` для явной конверсии (глава 8).
- `for` с условием и шагом.
- `if/else if/else` для трёх веток сравнения.
- `continue` для пропуска неверного ввода.
- `break` для выхода при выигрыше.
- Логическое НЕ (`!won`).

Поиграйте, попробуйте сломать (введите букву вместо числа — что будет?), потом исправьте.

## Маленькое упражнение

1. Напишите программу, которая печатает таблицу умножения 10×10:
   ```
    1  2  3 ...
    2  4  6 ...
    3  6  9 ...
   ```
   Подсказка: вложенный `for`.

2. Напишите программу, которая читает числа из stdin до нуля и считает сумму:
   ```
   $ ./sum
   5
   3
   7
   0
   Сумма: 15
   ```
   Подсказка: `while (true) { ... if (x == 0) break; }`.

3. Напишите программу, которая находит первое простое число больше N (N — ввод пользователя).

4. Напишите программу-калькулятор: на вход — два числа и операция (`+ - * /`), на выход — результат. Используйте `switch` по операции.

5. (Сложнее) Напишите программу, которая для каждого числа от 1 до 100:
   - если делится на 3 — печатает «Fizz»;
   - если на 5 — «Buzz»;
   - если и на 3, и на 5 — «FizzBuzz»;

   Это классическая задача FizzBuzz на собеседованиях.

Если не получается с первого раза — нормально. Если получается с третьего — отлично. Если получилось всё с первого — впечатляет. В любом случае запускайте и проверяйте каждую программу.
