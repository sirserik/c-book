# Глава 6. Инструменты и первая программа

В этой главе мы поставим C++-компилятор, выберем редактор, напишем самую простую программу, соберём её и запустим. И главное — на каждом шаге я объясню, что именно происходит. Не «вот команда, запустите её», а «вот команда, и теперь покажу, что за этой командой стоит на самом деле».

## Что нам нужно

Для C++-разработки нужны три вещи:

1. **Компилятор** — программа, которая превращает текст вашей программы (`.cpp`-файл) в исполняемый файл, который умеет запускать процессор.
2. **Текстовый редактор** — где вы пишете этот текст. Любой подойдёт; современные редакторы дополнительно подсказывают синтаксис и подсвечивают ошибки.
3. **Терминал** — программа, в которой вы пишете команды операционной системе. Команды вроде «скомпилируй мне вот этот файл» или «запусти вот этот исполняемый файл». Терминал есть в любой ОС, просто называется по-разному.

Иногда к этому добавляют **отладчик** (программа, которая позволяет остановить вашу программу в любой точке и посмотреть значения переменных) и **систему сборки** (программа, которая знает, какие файлы и в каком порядке компилировать в большом проекте). Их мы поставим, но не в этой главе.

Идём по платформам.

## macOS

На современном Mac (любом, начиная с 2010-х) компилятор называется **clang**. Apple встроила его в систему — вернее, в инструмент Xcode Command Line Tools.

Откройте терминал (Cmd+Space → «Terminal» → Enter) и введите:

```bash
$ clang++ --version
```

Если в ответ вы видите что-то вроде `Apple clang version 14.0.3 (clang-1403.0.22.14.1)` — компилятор у вас уже есть, переходим к редактору.

Если же терминал предложит установить инструменты разработчика (появится окошко с большой кнопкой «Install») — нажмите её. Через несколько минут установка закончится, и команда `clang++ --version` начнёт работать. На современных Mac с Apple Silicon Xcode Command Line Tools идут как ~700 МБ — это нормально.

Полную Xcode IDE ставить **не нужно** — она огромная (десятки гигабайт), и для нашей книги избыточна. Хватит командной строки.

Альтернатива clang — **gcc** (про него поговорим в Linux-разделе). Поставить его на macOS можно через Homebrew (`brew install gcc`), но смысла особого нет: Apple clang делает всё то же самое. Я буду писать команды как с `g++`, так и с `clang++` — на macOS можете использовать любой, результат будет одинаков. По умолчанию даже команда `g++` на macOS вызывает clang (Apple подсунула символическую ссылку).

## Linux

На Ubuntu/Debian и их производных:

```bash
$ sudo apt update
$ sudo apt install build-essential
```

Пакет `build-essential` содержит **gcc/g++** (GNU Compiler Collection — компилятор разрабатывается с 1987 года, считается «эталоном» в Linux-мире) плюс инструменты вроде `make` и `libc6-dev` (заголовки стандартной библиотеки). Проверка:

```bash
$ g++ --version
g++ (Ubuntu 11.4.0-1ubuntu1~22.04) 11.4.0
```

На Fedora/RHEL/CentOS:

```bash
$ sudo dnf install gcc-c++ make
```

На Arch:

```bash
$ sudo pacman -S base-devel
```

Если хотите clang — поставьте отдельно: `sudo apt install clang` или эквивалент. Иметь оба не вредно — на больших проектах удобно собирать обоими по очереди, потому что они выдают разные предупреждения, и баги ловятся лучше.

## Windows

С Windows ситуация чуть хитрее, потому что нативный «виндовый» компилятор — Microsoft Visual C++ из Visual Studio — отличается от Linux-овского g++ многими мелочами (синтаксис командной строки, заголовочные файлы, флаги). Я в книге везде пишу команды для g++/clang++, потому что они одинаковые на macOS и Linux.

У вас три варианта.

**Вариант A — WSL2 (Windows Subsystem for Linux), рекомендую.** Microsoft встроила в Windows 10/11 полноценный Linux. Откройте PowerShell от администратора и наберите:

```powershell
> wsl --install
```

Перезагрузитесь. После перезагрузки в меню «Пуск» появится Ubuntu — запустите, придумайте имя пользователя и пароль, и у вас теперь Linux внутри Windows. Дальше следуйте инструкциям из секции «Linux» (`sudo apt install build-essential`). Все команды из книги будут работать «как на Linux».

**Вариант B — MSYS2.** Это среда, которая ставит на Windows полноценный GNU-toolchain (g++, make, всё как в Linux), но без виртуализации. Скачать: https://www.msys2.org/. После установки откройте «MSYS2 MINGW64» и наберите:

```bash
$ pacman -S mingw-w64-x86_64-gcc mingw-w64-x86_64-clang
```

Дальше команда `g++` будет работать. Минус: пути с обратными слешами и другие мелочи Windows иногда вылезают.

**Вариант C — Visual Studio Community.** Полная IDE от Microsoft, бесплатная для индивидуальной разработки. При установке выберите workload «Desktop development with C++». После этого в меню появится «Developer Command Prompt» — это терминал, где работает команда `cl` (это виндовый компилятор; синтаксис другой, но первые программы соберёт). Подойдёт, но мои команды надо будет адаптировать.

Я в книге дальше пишу команды для g++/clang++. Если вы на Windows и выбрали вариант C — открывайте дополнительную вкладку с документацией Microsoft по `cl.exe` и сопоставляйте флаги. Если выбрали A или B — у вас всё будет совпадать с macOS/Linux.

## Редактор

C++ можно писать в Notepad. Я серьёзно — буква в букву это совпадает с тем, как писали в 90-х. Но мы живём в 2026, и есть выбор получше.

**VS Code** — бесплатный, лёгкий, отлично работает с C++ через расширение «C/C++» от Microsoft и/или «clangd» (более современная альтернатива). Установка: https://code.visualstudio.com/, потом в боковой панели Extensions поставьте «C/C++» или «clangd». На macOS/Linux/Windows работает одинаково.

**Sublime Text** или **Vim/Neovim** — для тех, кто предпочитает классику. Vim требует настройки (plugin clangd), но после неё — летает.

**CLion** от JetBrains — полноценная IDE с самой умной автодополнялкой и встроенным отладчиком, но платная (студенческая лицензия бесплатно). Если вы любите среду JetBrains (PHPStorm, IntelliJ, PyCharm) — поставьте, разница только в языке.

**Я в книге исхожу из того, что у вас VS Code.** Это самый распространённый вариант в 2026 году, бесплатно, и достаточно мощно. Все скриншоты — оттуда. Если у вас другой редактор — большой разницы нет, в книге почти не будет «нажмите Ctrl+Shift+P».

## Структура проекта

Создайте где-нибудь на диске папку для нашей книги. Я кладу свои учебные проекты в `~/code/cpp-book/` на macOS (`~` — это домашняя папка пользователя). Откройте терминал и создайте папку:

```bash
$ mkdir -p ~/code/cpp-book/ch01
$ cd ~/code/cpp-book/ch01
```

Команда `mkdir` (make directory) создаёт папку. Флаг `-p` означает «и все промежуточные тоже, если их нет». Команда `cd` (change directory) переходит в эту папку.

Откройте эту папку в VS Code:

```bash
$ code .
```

Точка `.` означает «текущая папка». Если команды `code` нет — в VS Code откройте Command Palette (Cmd+Shift+P на mac, Ctrl+Shift+P на остальных) и выполните «Shell Command: Install 'code' command in PATH».

## Первая программа — `hello.cpp`

В открытом VS Code создайте файл `hello.cpp` (правой кнопкой по дереву файлов слева → New File). Расширение `.cpp` — стандартное для исходников C++. Бывают ещё `.cxx`, `.cc`, `.C` — это всё C++; конкретно `.cpp` — самое распространённое.

Напишите туда:

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, world!" << std::endl;
    return 0;
}
```

Шесть строк (с пустой между ними). Сейчас разберём каждый символ. Серьёзно — каждый.

### Строка 1: `#include <iostream>`

Это директива препроцессора. **Препроцессор** — это первая стадия компиляции; он читает исходник, обрабатывает строчки, начинающиеся с `#`, и подменяет их на что-то другое. В нашем случае — берёт содержимое файла `iostream` и вставляет его прямо сюда, где написано `#include`.

Файл `iostream` — это часть стандартной библиотеки C++. Внутри него — описания того, как работать с вводом и выводом (input/output stream). Конкретно нам сейчас нужно `std::cout` — объект, который представляет «стандартный вывод» (то, куда пишет ваша программа: обычно это терминал). Объект `std::cout` объявлен где-то внутри `<iostream>`, поэтому без `#include <iostream>` компилятор не будет знать, что такое `std::cout`, и выдаст ошибку.

Угловые скобки `<...>` говорят: ищи этот файл в системных папках стандартной библиотеки (на macOS это что-то вроде `/Library/Developer/CommandLineTools/usr/include/c++/v1/`, а на Linux — `/usr/include/c++/11/`). Если бы мы написали `#include "iostream"` в кавычках — препроцессор сначала смотрел бы в папке нашего исходника, а только потом в системных. Это правило используется, когда вы подключаете *свои* заголовочные файлы (не стандартные).

`iostream` без расширения — это особенность стандартной библиотеки C++. Когда-то (давно) подключали `<iostream.h>`. В современном C++ — без `.h`. Под капотом файл всё равно есть, просто называется чуть иначе и лежит в специальной папке.

Заметьте: в конце строки **нет точки с запятой**. Препроцессорные директивы — особый случай; они обрабатываются ещё до того, как начинает работать собственно компилятор. Точка с запятой им не нужна, и если её поставить — будет ошибка.

### Строка 2: пустая

Просто разделитель. Компилятор её игнорирует. Я люблю отделять блок `#include` от кода пустой строкой — это визуально структурирует файл. Можно не делать.

### Строка 3: `int main() {`

Это начало функции `main`. Функция `main` — особенная: это точка входа в программу. Когда вы запускаете исполняемый файл, операционная система ищет в нём функцию с именем `main` и вызывает её. Если такой функции нет — программа не соберётся.

Разберём по частям.

`int` — это **тип возвращаемого значения**. Функция `main` возвращает целое число (`int` = integer). Это число — код возврата программы. По умолчанию `0` означает «всё прошло хорошо», ненулевое значение — «что-то сломалось». Этим кодом возврата пользуются shell-скрипты: они проверяют, успешно ли отработала ваша программа, чтобы решить, продолжать или нет.

`main` — имя функции. Это **зарезервированное имя** в C++ — нельзя сделать `main` чем-то другим (например, переменной).

`()` — пустые круглые скобки. Это **список параметров функции**. Сейчас он пуст; на самом деле `main` в C++ может принимать аргументы командной строки (`int main(int argc, char* argv[])`), но мы пока без них.

`{` — открывающая фигурная скобка. Это начало **тела функции**. Всё, что идёт от `{` до соответствующей `}`, выполняется при вызове функции. В C++ блоки кода всегда выделяются фигурными скобками — никаких отступов как в Python.

### Строка 4: `    std::cout << "Hello, world!" << std::endl;`

Это **выражение-инструкция** — основной строительный кирпичик любой C++ программы. Разбираем по кускам.

**Четыре пробела в начале строки.** Это отступ. Чисто визуально — чтобы было видно, что строка принадлежит телу функции `main`. Компилятор отступы игнорирует; они для человека. В команде обычно договариваются: 4 пробела или 2 пробела или tab. В книге я использую 4 пробела. Большинство C++-стандартов в отрасли — тоже 4 пробела (Google C++ Style Guide — 2 пробела, но в нашей книге держимся 4).

**`std::cout`** — обращение к объекту `cout` из пространства имён `std`. **Пространство имён** (namespace) — это что-то вроде «папки» для имён, чтобы две библиотеки могли использовать одинаковые названия и не конфликтовать. Вся стандартная библиотека C++ живёт в пространстве `std`. Чтобы добраться до объекта внутри, пишут `имя_пространства::имя_объекта`. Двоеточия — две штуки подряд (`::`) — называются *оператором разрешения области видимости*.

Объект `cout` — это «стандартный поток вывода». Он наследник класса `std::ostream`. Технически это объект, у которого есть состояние (например, текущая позиция, флаги форматирования), и который умеет принимать данные и отправлять их в терминал.

**Оператор `<<`** — это **оператор вставки в поток**. Читается так: «отправь в `cout` то, что справа». То есть `std::cout << "Hello, world!"` означает «отправь строку `"Hello, world!"` в стандартный вывод». Само сочетание `<<` для битового сдвига влево используется (это тот же символ), но в контексте `std::cout` оно перегружено как «вставить в поток». Это перегрузка операторов — мощная вещь C++, доберёмся до неё в главе 11.

**`"Hello, world!"`** — это **строковый литерал**. Кавычки двойные. Тип у него — `const char[14]` (массив из 14 символов: 13 видимых + один невидимый «нулевой символ» `\0`, который маркирует конец строки в стиле C). Дальше эта штука неявно сконвертируется в `const char*` (указатель на первый символ массива), и `<<` этим займётся.

Внутри строкового литерала можно использовать **escape-последовательности**: `\n` — перевод строки, `\t` — табуляция, `\"` — кавычка внутри строки, `\\` — обратный слеш. Мы их пока не используем.

**Второй `<<` и `std::endl`** — снова оператор вставки, но теперь мы вставляем не строку, а специальный объект `std::endl`. Это «end line» — он делает две вещи: вставляет символ перевода строки (`'\n'`) и сбрасывает буфер вывода (то есть форсирует, чтобы текст реально появился в терминале, а не остался лежать в буфере).

В большинстве случаев вместо `std::endl` можно писать `"\n"` — это быстрее, потому что не сбрасывает буфер. Но для нашей первой программы `std::endl` нагляднее.

**Точка с запятой `;` в конце** — обязательна. В C++ почти каждая инструкция оканчивается точкой с запятой. Если её забыть, компилятор выдаст ошибку. Привыкайте сразу.

Итого: эта строка отправляет в стандартный вывод текст «Hello, world!» и перевод строки.

### Строка 5: `    return 0;`

Возврат из функции `main` со значением 0. Как мы говорили, `main` возвращает целое число — код возврата программы. `0` — «успех». `return` — ключевое слово, которое останавливает выполнение функции и отдаёт значение наружу. Точка с запятой в конце — снова обязательна.

В C++ для функции `main` есть особое правило: если вы забудете `return 0;`, компилятор автоматически добавит его сам. То есть для `main` `return 0;` опционален. Но я всегда пишу явно — так понятнее.

### Строка 6: `}`

Закрывающая фигурная скобка. Конец тела функции `main`. На этом файл и заканчивается.

## Компиляция

Сохранили файл (Cmd+S на mac, Ctrl+S на остальных). Теперь в терминале:

```bash
$ g++ -std=c++11 -Wall -Wextra hello.cpp -o hello
```

Если у вас вместо g++ есть только clang++ — пишите clang++, всё то же самое:

```bash
$ clang++ -std=c++11 -Wall -Wextra hello.cpp -o hello
```

Разбираем по флагам.

**`g++`** или **`clang++`** — собственно компилятор. Можно ещё `c++` (это символическая ссылка, обычно на системный C++-компилятор).

**`-std=c++11`** — какой стандарт языка использовать. Без этого флага компилятор может взять стандарт по умолчанию (у gcc 11+ это C++17, у clang старее — C++98). Мы фиксируем `-std=c++11`, чтобы код собирался у всех читателей одинаково. Иногда увидите `-std=c++14`, `-std=c++17`, `-std=c++20`, `-std=c++23` — это более новые стандарты.

**`-Wall`** — включить большую часть стандартных предупреждений. `W` = warning, `all` — все. Предупреждения это не ошибки — компилятор просто говорит: «ты тут что-то странное написал, может быть, опечатка?» Хорошая практика — всегда собирать с `-Wall`.

**`-Wextra`** — включить ещё больше предупреждений, которые не вошли в `-Wall`. Тоже очень полезно.

**`-pedantic`** — иногда добавляю. Это «педантичный» режим: компилятор требует строгого соответствия выбранному стандарту, без расширений GNU/clang. Для книги полезно: если код собирается с `-pedantic`, значит, он стандартный.

**`hello.cpp`** — имя файла с исходным кодом. Можно несколько: `g++ a.cpp b.cpp c.cpp`.

**`-o hello`** — имя выходного файла. `-o` от output. Без этого флага компилятор по умолчанию назовёт результат `a.out` (наследие 70-х, когда так называли исполняемые файлы на Unix). Я предпочитаю явно говорить, как назвать.

Если всё хорошо — никакого вывода не будет. Это normal: «no news is good news» в Unix-философии. Зато в папке появится файл `hello` (или `hello.exe` на Windows). Проверим:

```bash
$ ls -lh hello
-rwxr-xr-x  1 user  staff   33K hello
```

Файл размером ~33 KB. Видите `x` в правах доступа (`rwxr-xr-x`) — это «executable», его можно запустить.

## Запуск

```bash
$ ./hello
Hello, world!
```

Точка-слеш в начале (`./`) — это **обязательно**. В Unix-системах, когда вы пишете `hello` без `./`, shell ищет программу с таким именем в специальных папках (`/usr/bin`, `/bin`, `/usr/local/bin`, и так далее — это переменная `$PATH`). Текущую папку он *не* проверяет — из соображений безопасности (чтобы вы случайно не запустили вредоносный `ls` в каком-нибудь скачанном архиве, подменивший системный). Чтобы явно сказать «запусти программу из текущей папки», используют `./` — точка означает текущую папку, слеш — разделитель.

Программа выполнилась, вывела «Hello, world!», и закончилась. Если хотите увидеть код возврата:

```bash
$ echo $?
0
```

Команда `echo $?` показывает код возврата последней запущенной программы. У нас `0`, потому что мы написали `return 0;`. Поменяйте на `return 42;`, пересоберите, запустите, проверьте — увидите 42.

## Что произошло — большая картинка

Между моментом, когда вы написали `g++ hello.cpp -o hello`, и моментом, когда появился исполняемый файл, прошло четыре стадии компиляции. Я расскажу о них коротко сейчас, а детально — в следующей главе.

**Стадия 1: препроцессор.** Компилятор берёт `hello.cpp` и обрабатывает все `#include`. То есть он буквально берёт содержимое файла `iostream` (а это десятки тысяч строк, потому что внутри ещё много `#include`) и подставляет его в место `#include <iostream>`. На выходе — один огромный «развёрнутый» исходник. Хотите увидеть? `g++ -E hello.cpp` (E от «preprocess»). Не пугайтесь, вылетит много текста.

**Стадия 2: компилятор.** Из «развёрнутого» исходника генерируется *ассемблерный код* — текст на низкоуровневом языке процессора. Хотите увидеть? `g++ -S hello.cpp -o hello.s`. Потом откройте `hello.s` — увидите инструкции вроде `movq`, `callq`, `retq`. Это уже почти машинный код, только в текстовом виде.

**Стадия 3: ассемблер.** Из ассемблерного текста делается *объектный файл* — бинарный файл, содержащий машинный код, но ещё не «соединённый» с другим кодом. `g++ -c hello.cpp -o hello.o`. Файл `hello.o` — это машинный код вашей функции `main`, но с «дырками» там, где она ссылается на чужие функции (например, на `std::cout::operator<<`).

**Стадия 4: линкер.** Линкер берёт все объектные файлы и подставляет в «дырки» реальные адреса. Например, наша программа ссылается на `std::cout`, который реализован в стандартной библиотеке (на macOS — `libc++`, на Linux — `libstdc++`). Линкер находит библиотеку, привязывает её, и получается готовый исполняемый файл.

Когда вы пишете `g++ hello.cpp -o hello` без флагов `-E`, `-S`, `-c` — компилятор молча проходит все четыре стадии и выдаёт готовый файл. Под капотом это четыре отдельных программы (`cpp`, `cc1plus`, `as`, `ld`), и `g++` их вызывает по очереди. Можете в этом убедиться: `g++ -v hello.cpp -o hello` покажет всё, что происходит, с подробными командами.

Глава 2 будет именно про это: компиляция по шагам, объектные файлы, символы, линковка. Сейчас же запомните: исходник `.cpp` не запускается напрямую. Он сначала превращается в исполняемый файл, и уже исполняемый файл запускает процессор.

## Что если ошибка

Сломаем нашу программу нарочно — уберите точку с запятой в конце пятой строки:

```cpp
    return 0
}
```

Соберите:

```bash
$ g++ -std=c++11 hello.cpp -o hello
hello.cpp:6:1: error: expected ';' before '}' token
    6 | }
      | ^
```

Компилятор честно говорит: «На строке 6 в начале я ждал точку с запятой перед `}`, но не нашёл». Сообщения об ошибках в современном gcc/clang очень подробные — внимательно читайте их, не пугайтесь объёма. Обычно ошибка ровно там, где компилятор её показал.

Несколько типичных ошибок, с которыми вы столкнётесь в первые дни:

**`error: 'cout' was not declared in this scope`** — забыли `#include <iostream>` или забыли `std::` перед `cout`.

**`undefined reference to 'main'`** — забыли написать функцию `main` (или назвали её по-другому).

**`expected ';' before ...`** — где-то выше потеряли точку с запятой.

**`'std' has not been declared`** — старый компилятор, который не понимает `std::`. Поставьте новый.

**`no such file or directory: 'iostream'`** — у вас не установлена стандартная библиотека C++ (бывает на минималистичных Linux-сборках). Поставьте `libstdc++-dev` или эквивалент.

## Запоминания на сегодня

К следующей главе хорошо бы выучить наизусть:

- Каждый исполняемый файл — это результат компиляции одного или нескольких `.cpp` файлов плюс линковки с библиотеками.
- Функция `main` — точка входа в программу. Возвращает `int`.
- Каждый блок кода обрамляется фигурными скобками `{...}`.
- Каждая инструкция оканчивается точкой с запятой `;`.
- `#include <...>` подключает заголовочный файл.
- Пространство имён `std` — это вся стандартная библиотека. Доступ через `std::имя_объекта`.
- `std::cout << ...` — вывод. `<<` — оператор вставки в поток.
- `std::endl` — перевод строки + сброс буфера.
- Команда сборки: `g++ -std=c++11 -Wall -Wextra файл.cpp -o имя`.
- Запуск программы в текущей папке: `./имя`.

## Маленькое упражнение

Чтобы рука запомнила синтаксис, напишите программу, которая выводит:

```
Меня зовут Ваше Имя.
Я учу C++.
Это моя первая программа.
```

Можете использовать `std::endl` или `"\n"` для переводов строки — попробуйте оба варианта. Откройте файл `intro.cpp`, напишите код, соберите, запустите. Если соберётся с первого раза — это очень хороший знак. Если нет — внимательно прочтите ошибку и попробуйте найти, где забыли точку с запятой или скобку. Это первый и самый частый источник ошибок в C++.
