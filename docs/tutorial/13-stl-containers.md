# Глава 13. Контейнеры STL

Стандартная библиотека C++ даёт целый зоопарк готовых контейнеров. Это огромное преимущество языка — почти любую задачу хранения данных закрывает что-то стандартное, и писать своё не надо. В этой главе разберём основные: `vector`, `array`, `list`, `map`, `unordered_map`, `set`, `unordered_set`. Расскажу, как они устроены изнутри, что у каких быстро/медленно, и в каком случае какой выбирать.

Эта глава очень практическая. Контейнеры — то, чем вы будете пользоваться **постоянно** в любом коде на C++. Без свободного владения хотя бы `vector` далеко не уехать.

## Зачем контейнеры

В Python вы пишете `[1, 2, 3]` — это список. `{1, 2, 3}` — множество. `{"a": 1}` — словарь. Под капотом всё это разные структуры данных, но интерфейс однообразный и удобный.

В C++ исторически был только сырой массив (`int arr[10]`), который мы рассмотрели в главе 11. У него есть проблемы: размер на этапе компиляции, не растёт, нет удобных операций. Поэтому в стандартную библиотеку добавили контейнеры — каждый со своей структурой данных и интерфейсом.

Все контейнеры являются **шаблонами** (templates) — вы указываете, какой тип они будут хранить:

```cpp
std::vector<int> numbers;          // вектор целых
std::vector<std::string> names;     // вектор строк
std::vector<std::vector<int>> grid; // вектор векторов (двумерная таблица)
```

Про шаблоны подробно — в главе 20. Сейчас достаточно знать: `Container<T>` — это контейнер, хранящий элементы типа `T`.

Все контейнеры — **RAII-объекты**. Они владеют своими данными, копируются и удаляются корректно, никаких ручных `delete` не нужно.

## std::vector — главный контейнер

Если бы пришлось выбрать **один** контейнер на всю программу — выбрали бы `vector`. На моих проектах он покрывает 80% всех случаев хранения данных.

Это **динамический массив**: элементы лежат в памяти подряд, размер может расти. Подключается через `<vector>`:

```cpp
#include <vector>
```

### Создание

```cpp
std::vector<int> a;                   // пустой
std::vector<int> b(10);                // 10 элементов, все 0
std::vector<int> c(10, 42);            // 10 элементов, все 42
std::vector<int> d{1, 2, 3, 4, 5};     // initializer list — 5 указанных элементов
std::vector<int> e = {1, 2, 3};        // тоже initializer list
std::vector<int> f(c);                 // копия c

std::cout << d.size();   // 5
```

`std::vector<int> v(10)` и `std::vector<int> v{10}` — **разные**! Первое — «10 нулей», второе — «один элемент 10» (инициализация-списком). Это та самая ловушка `()` vs `{}` из главы 8. Будьте внимательны.

### Доступ к элементам

```cpp
std::vector<int> v = {10, 20, 30, 40};

int x = v[0];           // 10 (без проверки границ)
int y = v.at(1);        // 20 (с исключением при выходе за границу)

int first = v.front();   // 10
int last  = v.back();    // 40
```

`v[i]` быстрее, чем `v.at(i)` (нет проверки), но опаснее. В новом коде с непроверенными индексами я обычно использую `[]` плюс ручной `assert(i < v.size())` в отладке.

### Добавление и удаление

```cpp
std::vector<int> v;

v.push_back(1);   // [1]
v.push_back(2);   // [1, 2]
v.push_back(3);   // [1, 2, 3]

v.pop_back();     // [1, 2]

v.insert(v.begin() + 1, 99);    // [1, 99, 2] — вставить перед позицией 1
v.erase(v.begin());              // [99, 2] — удалить первый

v.clear();        // []
```

`push_back` — **главная** операция, добавление в конец. **Амортизированно O(1)** — обычно мгновенно, иногда долго (при росте capacity, об этом ниже).

`insert` и `erase` в середине — **O(n)**: нужно сдвинуть все элементы, которые идут после. Не используйте `insert` для частых вставок не в конец.

### Размер и ёмкость

Здесь начинается самое интересное. У `vector` есть **два** размера:

- **`size()`** — сколько элементов реально хранится.
- **`capacity()`** — сколько элементов может поместиться без новой аллокации памяти.

```cpp
std::vector<int> v;
std::cout << v.size() << " " << v.capacity() << "\n";  // 0 0

v.push_back(1);
std::cout << v.size() << " " << v.capacity() << "\n";  // 1 1

v.push_back(2);
std::cout << v.size() << " " << v.capacity() << "\n";  // 2 2

v.push_back(3);
std::cout << v.size() << " " << v.capacity() << "\n";  // 3 4

v.push_back(4);
std::cout << v.size() << " " << v.capacity() << "\n";  // 4 4

v.push_back(5);
std::cout << v.size() << " " << v.capacity() << "\n";  // 5 8
```

Размер растёт по 1. Ёмкость — **скачками**: 0 → 1 → 2 → 4 → 8 → 16 → 32. На GCC (libstdc++) и clang (libc++) это умножение на 2, на MSVC — на 1.5. Каждое «уплотнение» — это:

1. Выделить новую память (вдвое больше).
2. Скопировать (или переместить — об этом в главе 19) старые элементы.
3. Уничтожить старые.
4. Освободить старую память.

Это медленно. Но **амортизированная** сложность всё равно O(1): если рост экспоненциальный, то операций «скопировать N элементов» происходит редко (логарифм от размера), и общее время на N вставок — O(N).

### reserve и оптимизация

Если **заранее известно**, сколько элементов будет — лучше зарезервировать:

```cpp
std::vector<int> v;
v.reserve(1000);              // capacity = 1000 заранее
for (int i = 0; i < 1000; ++i) {
    v.push_back(i);            // ни одной реаллокации
}
```

`reserve(N)` гарантирует: первые N `push_back` пройдут без перевыделения памяти. Хорошая привычка, когда размер можно прикинуть.

`shrink_to_fit()` — обратное: убрать запас, сделать `capacity() == size()`. Используется редко, обычно когда хотите вернуть ОС лишнюю память.

### Инвалидация итераторов и указателей

Серьёзная ловушка `vector`. После любой операции, которая может вызвать **перевыделение** памяти (`push_back`, `insert`, `reserve`, ...), все указатели и итераторы на элементы **становятся невалидными**.

```cpp
std::vector<int> v = {1, 2, 3};

int* p = &v[0];           // p указывает на первый элемент
v.push_back(4);
v.push_back(5);
v.push_back(6);            // одно из этих push_back вызвало реаллокацию

*p = 99;                   // UB! p указывает на старую освобождённую память
```

То же с итераторами. То же с `range-based for`:

```cpp
std::vector<int> v = {1, 2, 3};
for (int& x : v) {
    if (x == 2) {
        v.push_back(99);   // UB! Меняем контейнер во время итерации
    }
}
```

**Правило**: пока вы итерируете по вектору, **не меняйте его** — не добавляйте, не удаляйте, не вызывайте `reserve`. Если нужно — итерируйте по индексам и заранее запоминайте размер:

```cpp
size_t n = v.size();
for (size_t i = 0; i < n; ++i) {
    if (v[i] == 2) {
        v.push_back(99);   // OK, n зафиксировано
    }
}
```

Или собирайте «что добавить» в отдельный список, и добавляйте после цикла.

### Почему vector обычно быстрее списка

Элементы `vector` лежат в памяти **подряд**. Это значит:
- При доступе к `v[i]` адрес вычисляется как `&v[0] + i * sizeof(T)` — одна арифметическая операция.
- При проходе подряд процессор подгружает соседние элементы в кэш сразу. Это очень быстро.
- Никаких «прыжков» по адресам, никаких разыменований указателей.

Сравните с **связным списком**: каждый элемент — отдельный узел на куче, с указателем на следующий. Чтобы перейти к следующему, нужно прочитать указатель — это обращение в RAM (кэш-промах) → ~200 тактов.

В среднем, проход по `vector<int>` из миллиона элементов — миллисекунды. По `list<int>` — десятки миллисекунд. Разница в 10-50 раз. Это про **кэш-дружелюбность**, о которой я говорил в главе 1.

Поэтому современный C++ совет: **используйте `vector` по умолчанию**. Список бери только если есть очень особые причины.

### Удаление-стирание идиома (erase-remove)

Удалить **все** элементы, удовлетворяющие условию:

```cpp
std::vector<int> v = {1, 2, 3, 4, 5, 6};
// убрать все чётные

v.erase(
    std::remove_if(v.begin(), v.end(),
                   [](int x) { return x % 2 == 0; }),
    v.end()
);
// v теперь {1, 3, 5}
```

Это идиома **erase-remove**. `std::remove_if` сдвигает «оставляемые» элементы в начало и возвращает итератор «за концом нужного». `erase` удаляет хвост. Лямбды и алгоритмы — главы 14 и 21, но идиому стоит знать.

В C++20 есть прямой `std::erase_if(v, predicate)`, но в C++11 — только составной приём.

## std::array — массив фиксированного размера

`std::array<T, N>` — обёртка над сырым массивом, но с интерфейсом вектора. Размер **фиксирован на компиляции**, элементы лежат на стеке.

```cpp
#include <array>

std::array<int, 5> a = {1, 2, 3, 4, 5};

std::cout << a.size();   // 5 (всегда константа)
std::cout << a[0];        // 1
a.front();
a.back();

for (int x : a) {
    std::cout << x;
}
```

Когда брать `array`:
- Размер заранее известен и не меняется (например, RGB-цвет = `array<unsigned char, 3>`).
- Хотим то же удобство, что у `vector`, но без аллокации на куче.

Когда `vector`:
- Размер меняется.
- Размер известен только в рантайме.
- Размер очень большой (не уместится на стеке).

Размер `std::array` — это часть его типа. `std::array<int, 5>` и `std::array<int, 10>` — **разные типы**. Поэтому функция, принимающая `array`, должна знать размер на компиляции. Передача массивов разных размеров — тема шаблонов (глава 20).

## std::deque — двусторонняя очередь

`deque` (double-ended queue, читается «дэк») — как `vector`, но эффективно добавляет и удаляет с **обоих концов**:

```cpp
#include <deque>

std::deque<int> d;
d.push_back(1);
d.push_back(2);
d.push_front(0);     // эффективно, в отличие от vector::insert(begin(), ...)
// d = [0, 1, 2]
```

Внутри — список «блоков» (массивов небольшого размера). Поэтому индексация O(1), но элементы **не подряд в памяти** — кэш-эффективность хуже, чем у `vector`.

Когда брать: реальная очередь FIFO, иногда буферы. На практике — редко. `vector` хватает в 90% случаев.

## std::list — двусвязный список

`std::list` — двусвязный список (у каждого узла указатели на следующий и предыдущий).

```cpp
#include <list>

std::list<int> l = {1, 2, 3, 4, 5};
l.push_back(6);
l.push_front(0);

// нет индексации! l[2] не компилируется
auto it = l.begin();
std::advance(it, 2);     // перейти на 3-ю позицию
std::cout << *it;         // 3
```

Преимущества:
- Вставка/удаление в **середине** — O(1), если у вас уже есть итератор на нужное место.
- Итераторы **не инвалидируются** при добавлении/удалении (кроме удалённого).

Недостатки:
- Доступ по индексу — O(N), потому что нужно пройти от начала.
- Каждый узел — отдельная аллокация на куче (24 байта overhead на узел плюс выравнивание). Огромный overhead для маленьких элементов.
- Плохая кэш-эффективность.

Когда брать `list`:
- Очень частые вставки/удаления в середину.
- Стабильные итераторы важны.

В моей практике `list` нужен раз в год. Для большинства случаев — `vector`.

## std::map — упорядоченный словарь

`std::map<K, V>` — словарь, отображающий ключи `K` в значения `V`. Реализован как **красно-чёрное дерево** (балансированное двоичное дерево поиска).

```cpp
#include <map>

std::map<std::string, int> ages;
ages["Alice"] = 30;
ages["Bob"] = 25;
ages["Charlie"] = 42;

std::cout << ages["Alice"];   // 30
std::cout << ages.size();      // 3

// Проверка наличия
if (ages.count("Alice") > 0) ...           // C++11 способ
if (ages.find("Alice") != ages.end()) ...   // более общий способ

// Удаление
ages.erase("Bob");

// Обход — отсортированно по ключу
for (const auto& pair : ages) {
    std::cout << pair.first << " = " << pair.second << "\n";
}
// "Alice = 30"
// "Charlie = 42"
```

Главные свойства:
- **Все операции O(log N)** — find, insert, erase. Это не «быстро», но прилично.
- **Элементы отсортированы по ключу**. При обходе вы получите их по возрастанию.
- **Стабильные итераторы**: операции с другими элементами не инвалидируют итератор на элемент.

### Ловушка [] на map

`map[key]` имеет **побочный эффект**:

```cpp
std::map<std::string, int> ages;
ages["Alice"] = 30;
std::cout << ages["Bob"];    // 0, и Bob появился в карте с значением 0!
std::cout << ages.size();    // 2 !
```

Если ключа нет, `[]` **создаёт** его со значением по умолчанию (для `int` — 0, для `std::string` — пустая). Это иногда удобно (счётчики), иногда — опасно.

Безопасный доступ:

```cpp
auto it = ages.find("Bob");
if (it != ages.end()) {
    std::cout << it->second;
} else {
    std::cout << "не найден";
}
```

`it->first` — ключ, `it->second` — значение.

Или через `at`, который кидает исключение:

```cpp
try {
    int x = ages.at("Bob");
} catch (const std::out_of_range&) {
    std::cout << "не найден";
}
```

### Вставка с проверкой существования

```cpp
auto result = ages.insert({"Alice", 50});
if (result.second) {
    std::cout << "Добавлен\n";
} else {
    std::cout << "Alice уже была, значение " << result.first->second << "\n";
}
```

`insert` возвращает пару: итератор на элемент и `bool` «была ли вставка».

## std::unordered_map — хеш-таблица

`std::unordered_map<K, V>` — словарь на основе **хеш-таблицы**. Интерфейс тот же, что у `map`, но другие свойства:

```cpp
#include <unordered_map>

std::unordered_map<std::string, int> ages;
ages["Alice"] = 30;
ages["Bob"] = 25;

std::cout << ages["Alice"];   // 30
```

Главные свойства:
- **Поиск/вставка/удаление — O(1)** в среднем. **O(N) в худшем случае** (когда хеши плохо распределены, и все элементы попали в одно «ведро»).
- **Элементы НЕ отсортированы.** Обход — в произвольном порядке.
- **Перехеширование** при росте — инвалидация итераторов (как `vector` при `push_back`).

Когда брать `unordered_map`:
- Не нужно отсортированное хранение.
- Нужны быстрые операции.

Когда `map`:
- Нужен отсортированный обход.
- Нужно «найти первый элемент с ключом ≥ X» — есть `lower_bound`.
- Хочется стабильное поведение в худшем случае (`map` гарантированно O(log N), `unordered_map` может стать O(N)).

В большинстве случаев берите `unordered_map` — он быстрее.

### Ключи в unordered_map

Чтобы тип `K` мог быть ключом `unordered_map`, для него должна быть определена **функция хеширования**. Для стандартных типов (`int`, `std::string`, `double`) она уже есть. Для своих классов придётся определять — `std::hash<MyClass>::operator()`. Об этом коротко в главе 20.

### Что внутри unordered_map

Это массив **«вёдер»** (buckets). Хеш-функция превращает ключ в число; число делится по модулю на количество вёдер, получается индекс. В этом ведре лежит список (обычно односвязный) всех элементов с тем же индексом.

Если все элементы попадают в одно ведро — поиск становится O(N), потому что нужно пройти по списку. Хорошая хеш-функция распределяет равномерно, чтобы в каждом ведре было ~1 элемент.

## std::set и std::unordered_set

Те же, что `map`/`unordered_map`, но **без значения** — только ключи. То есть **множество**.

```cpp
#include <set>
#include <unordered_set>

std::set<std::string> taken_names;
taken_names.insert("Alice");
taken_names.insert("Bob");

if (taken_names.count("Charlie") == 0) {
    std::cout << "Charlie свободно\n";
}

std::unordered_set<int> visited;
visited.insert(5);
visited.insert(10);
```

Свойства:
- `set` — отсортированное, O(log N), на дереве.
- `unordered_set` — без сортировки, O(1) в среднем, на хеш-таблице.

Когда брать: проверка «есть ли», подсчёт уникальных, удаление дубликатов.

Простой алгоритм «убрать дубликаты из вектора»:

```cpp
std::vector<int> v = {1, 2, 2, 3, 3, 3, 4};
std::set<int> unique_set(v.begin(), v.end());
std::vector<int> unique(unique_set.begin(), unique_set.end());
// unique = {1, 2, 3, 4}, отсортированный
```

Через `unordered_set` — было бы быстрее, но порядок утратился бы.

## Итераторы — кратко

Все контейнеры поддерживают **итераторы** — обобщённый способ обхода. Это будем подробно в главе 14, но базово:

```cpp
std::vector<int> v = {10, 20, 30};

for (auto it = v.begin(); it != v.end(); ++it) {
    std::cout << *it << "\n";
}
```

- `v.begin()` — итератор на первый элемент.
- `v.end()` — итератор «за последний», sentinel.
- `++it` — следующий элемент.
- `*it` — значение по итератору.

`range-based for` под капотом — это `for` с итераторами. Тот же код:

```cpp
for (int x : v) {
    std::cout << x << "\n";
}
```

— компилируется в эквивалент классического `for (auto it = v.begin(); it != v.end(); ++it)`. Поэтому range-for работает для всего, у чего есть `begin()` и `end()`.

В главе 14 разберём, как использовать итераторы с алгоритмами.

## std::pair и std::tuple

Малые «контейнеры» для группировки разнородных значений.

`std::pair<A, B>` — пара:

```cpp
std::pair<std::string, int> entry{"Alice", 30};
std::cout << entry.first << ": " << entry.second;
```

Используется внутри `map` (элементы `map` — это `pair<key, value>`).

`std::tuple<A, B, C, ...>` — кортеж из нескольких значений (любого количества):

```cpp
#include <tuple>

std::tuple<std::string, int, double> t{"Alice", 30, 5.7};
std::cout << std::get<0>(t) << " " << std::get<1>(t) << " " << std::get<2>(t);
```

В C++17 появились structured bindings (`auto [name, age, height] = t;`), но в C++11 — через `std::get<N>(t)` или `std::tie(name, age, height) = t`.

Tuple используется нечасто; обычно лучше определить именованную struct.

## Сравнительная таблица

| Контейнер | Доступ по индексу | Вставка в конец | Вставка в начало | Вставка в середину | Поиск | Память |
|-----------|-------------------|-----------------|-------------------|-----|--|--|
| `vector` | O(1) | O(1) аморт. | O(N) | O(N) | O(N) | компактно, на куче |
| `array` | O(1) | — | — | — | O(N) | компактно, обычно на стеке |
| `deque` | O(1) | O(1) | O(1) | O(N) | O(N) | блочно, на куче |
| `list` | — | O(1) | O(1) | O(1) с итератором | O(N) | разрозненно, на куче |
| `map` | — | — | — | O(log N) | O(log N) | дерево на куче |
| `unordered_map` | — | — | — | O(1) среднее | O(1) среднее | хеш-таблица на куче |
| `set` | — | — | — | O(log N) | O(log N) | дерево на куче |
| `unordered_set` | — | — | — | O(1) среднее | O(1) среднее | хеш-таблица на куче |

## Решающее дерево: какой контейнер брать

```
Нужна последовательность с порядком?
├── Да: упорядочена и фиксирована? → array
│       упорядочена, размер меняется? → vector
│       часто вставляем и в начало, и в конец? → deque
│       очень частые вставки/удаления в середину? → list
└── Нет: нужны пары ключ-значение?
        ├── Да: нужен порядок ключей? → map
        │       только быстрый доступ? → unordered_map
        └── Нет (только уникальные элементы):
              нужен порядок? → set
              только быстрый доступ? → unordered_set
```

**По умолчанию — `vector` или `unordered_map`**. Они покрывают 90% случаев и в среднем самые быстрые благодаря кэш-эффективности и хешированию соответственно.

## Распространённые операции

### Найти элемент

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};

auto it = std::find(v.begin(), v.end(), 3);
if (it != v.end()) {
    std::cout << "Found at index " << (it - v.begin()) << "\n";
}
```

`std::find` из `<algorithm>` — работает с любым контейнером.

В `map` / `set` — встроенный `find` быстрее, потому что использует структуру (дерево или хеш):

```cpp
auto it = ages.find("Alice");
```

### Сортировка

```cpp
std::vector<int> v = {5, 2, 4, 1, 3};
std::sort(v.begin(), v.end());
// v = {1, 2, 3, 4, 5}

// По убыванию:
std::sort(v.begin(), v.end(), std::greater<int>());
// v = {5, 4, 3, 2, 1}
```

`std::sort` — алгоритм из главы 14. Работает для контейнеров с произвольным доступом (`vector`, `deque`, `array`). Не работает для `list` — у списка свой `sort` метод.

### Сумма

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};
int total = std::accumulate(v.begin(), v.end(), 0);
// 15
```

Третий аргумент — начальное значение. Можно использовать для произвольной операции (не только сложение), но это уже глава 14.

### Подсчёт

```cpp
std::vector<int> v = {1, 2, 2, 3, 2, 4};
int count = std::count(v.begin(), v.end(), 2);
// 3
```

### Уникальные значения

```cpp
std::vector<int> v = {1, 2, 2, 3, 3, 3, 4};
std::sort(v.begin(), v.end());
v.erase(std::unique(v.begin(), v.end()), v.end());
// v = {1, 2, 3, 4}
```

`std::unique` работает только на **отсортированных** — поэтому сначала `sort`.

## Большой пример: подсчёт частоты слов

Соберём программу, читающую текст и выводящую самые частые слова:

```cpp
#include <iostream>
#include <fstream>
#include <sstream>
#include <vector>
#include <unordered_map>
#include <string>
#include <algorithm>

int main(int argc, char* argv[]) {
    if (argc < 2) {
        std::cerr << "Usage: " << argv[0] << " <file>\n";
        return 1;
    }
    
    std::ifstream file(argv[1]);
    if (!file.is_open()) {
        std::cerr << "Cannot open " << argv[1] << "\n";
        return 1;
    }
    
    // Считаем частоту
    std::unordered_map<std::string, int> freq;
    std::string word;
    while (file >> word) {
        // Приведём к нижнему регистру (только ASCII — упрощение)
        for (char& c : word) {
            c = std::tolower(static_cast<unsigned char>(c));
        }
        // Уберём знаки препинания (упрощённо)
        word.erase(
            std::remove_if(word.begin(), word.end(),
                           [](char c) { return !std::isalpha(static_cast<unsigned char>(c)); }),
            word.end()
        );
        if (!word.empty()) {
            freq[word] = freq[word] + 1;
        }
    }
    
    // Переложим в вектор и отсортируем по убыванию частоты
    std::vector<std::pair<std::string, int>> pairs(freq.begin(), freq.end());
    std::sort(pairs.begin(), pairs.end(),
              [](const std::pair<std::string, int>& a,
                 const std::pair<std::string, int>& b) {
                  return a.second > b.second;
              });
    
    // Вывод первых 10
    int shown = 0;
    for (const auto& p : pairs) {
        std::cout << p.first << ": " << p.second << "\n";
        if (++shown >= 10) break;
    }
    
    return 0;
}
```

Использовано:
- `std::unordered_map<std::string, int>` для подсчёта (быстро, без сортировки).
- `std::vector<std::pair<...>>` для переноса в сортируемый формат.
- `std::sort` с лямбдой-компаратором (глава 14 + 21).
- `std::remove_if` для очистки от пунктуации.
- `range-based for` с `const auto&`.
- `argv` для имени файла.

Сборка:

```bash
$ g++ -std=c++11 -Wall -Wextra freq.cpp -o freq
$ ./freq book.txt
```

## Главные правила главы

1. **По умолчанию — `std::vector`** для последовательностей, **`std::unordered_map`** для словарей.
2. **`reserve`** перед циклом push_back, если знаете размер.
3. **Не модифицируйте контейнер во время `range-based for`** — UB.
4. **`map::[]` создаёт элемент**, если его не было. Используйте `find` или `at` для безопасного чтения.
5. **`list` нужен очень редко**. Не давайте в это «теории алгоритмов».
6. **Помните про инвалидацию итераторов** при изменении контейнера.
7. **`const T&` в range-for** для больших типов, без копий.
