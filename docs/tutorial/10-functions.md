# Глава 10. Функции

С функциями вы уже сталкивались — `main`, `std::cout`, и пара случайных штук. Эта глава — про то, как функции писать самим. Это огромная тема, потому что в C++ передача аргументов в функцию устроена сильно иначе, чем в Python или Java. У вас будет три способа передачи (по значению, по ссылке, по указателю), и каждый со своим смыслом. Я буду долго на этом останавливаться — это центральная вещь языка, и без её понимания дальше будет хаос.

## Зачем нужны функции

В главе 4 мы уже обсудили зачем — переиспользование, декомпозиция. Повторю кратко: функция позволяет один раз написать какой-то кусок логики и потом вызывать его сколько угодно раз. Это бережёт код от копи-пасты, делает структуру программы понятной и упрощает поиск ошибок (если ошибка в функции — правка одна, не пятнадцать).

Когда программа разрастается до тысяч строк — без функций жить нельзя. Хорошее правило: **если кусок кода вы скопировали два раза — пора вынести в функцию**.

## Анатомия функции

Вот простейшая функция:

```cpp
int square(int x) {
    return x * x;
}
```

Разбираем по частям.

- **`int`** в самом начале — **тип возвращаемого значения** (return type). Функция отдаёт обратно `int`. Если функция ничего не возвращает — пишут `void` (про это ниже).
- **`square`** — **имя функции**. Те же правила, что для переменных (буквы, цифры, подчёркивание; не начинается с цифры; не зарезервированное слово).
- **`(int x)`** — **список параметров**. У нашей функции один параметр типа `int` по имени `x`. Параметров может быть много, или ноль.
- **`{ ... }`** — **тело функции**. Код, который выполняется при вызове.
- **`return x * x;`** — возвращает значение из функции. Управление сразу переходит к месту вызова.

Вызов:

```cpp
int result = square(5);   // result = 25
```

Программа доходит до строки `int result = square(5);`, перепрыгивает в тело `square`, выполняет его (умножает 5 на 5, возвращает 25), потом возвращается обратно, и `result` получает значение 25.

### Несколько параметров

```cpp
int max(int a, int b) {
    if (a > b) return a;
    else       return b;
}
```

Можно иметь два, три, четыре параметра. У каждого свой тип и своё имя:

```cpp
double distance(int x1, int y1, int x2, int y2) {
    double dx = x2 - x1;
    double dy = y2 - y1;
    return std::sqrt(dx * dx + dy * dy);
}
```

(Здесь использован `std::sqrt` из `<cmath>` — квадратный корень.)

### void — функция без возврата

Если функция не должна ничего возвращать — указывайте `void`:

```cpp
void print_hello() {
    std::cout << "Hello!\n";
}
```

Вызов:

```cpp
print_hello();   // ничего не присваиваем
```

В `void`-функции можно писать `return;` (без значения) — это выход. Если функция дошла до конца тела без `return` — она тоже завершается, всё нормально:

```cpp
void greet(const std::string& name) {
    if (name.empty()) {
        return;   // выход досрочно
    }
    std::cout << "Hello, " << name << "!\n";
}
```

`return` в `void`-функции с значением — ошибка компиляции.

### Функция без параметров

Если параметров нет — пишут пустые скобки:

```cpp
int get_random() {
    return std::rand();
}
```

В C++ `()` означает «параметров нет», в отличие от C, где `()` означает «параметры неизвестны»; в C для «нет параметров» пишут `(void)`. В C++ обе формы работают, но `(...)` без `void` — стандарт.

## Объявление и определение

В главе 7 я мельком говорил: **объявление** функции — это обещание её существования, **определение** — это собственно её код.

Объявление:
```cpp
int square(int x);
```
(Точка с запятой в конце, тела нет.)

Определение:
```cpp
int square(int x) {
    return x * x;
}
```
(Полное, с телом.)

Зачем разделять? Чтобы можно было использовать функцию **до того, как она написана**. Компилятор работает сверху вниз: дойдя до строки `square(5)`, он должен уже знать, что такое `square`. Если функция определена ниже — компилятор не найдёт.

Поэтому обычно файл выглядит так:

```cpp
#include <iostream>

// объявления вверху
int square(int x);
int max(int a, int b);

// определения ниже
int main() {
    std::cout << square(5) << "\n";
    std::cout << max(3, 7) << "\n";
    return 0;
}

int square(int x) {
    return x * x;
}

int max(int a, int b) {
    return a > b ? a : b;
}
```

Альтернатива — определить функции **до** `main`:

```cpp
int square(int x) {
    return x * x;
}

int max(int a, int b) {
    return a > b ? a : b;
}

int main() {
    std::cout << square(5) << "\n";
    std::cout << max(3, 7) << "\n";
    return 0;
}
```

Если функция определена до использования — отдельное объявление не нужно. Каждое определение **само по себе** служит объявлением.

### Разделение между файлами

В программе из нескольких файлов схема такая. Допустим, у нас функция `square` нужна и в `main.cpp`, и в `tests.cpp`.

`math.h`:
```cpp
#ifndef MATH_H
#define MATH_H

int square(int x);     // объявление

#endif
```

`math.cpp`:
```cpp
#include "math.h"

int square(int x) {    // определение
    return x * x;
}
```

`main.cpp`:
```cpp
#include "math.h"

int main() {
    return square(5);
}
```

`tests.cpp`:
```cpp
#include "math.h"

void run_tests() {
    if (square(3) != 9) ...
}
```

Когда `main.cpp` и `tests.cpp` компилируются, они оба видят объявление `square` (через `#include "math.h"`). Компилятор не возражает — он не требует тела на этапе компиляции. Тело берётся при **линковке**, из `math.cpp`. Линкер находит реальную `square` в `math.o` и подставляет.

Это разделение «объявление в .h, определение в .cpp» — стандартный паттерн в C++. Заголовочный файл — публичный интерфейс модуля. Исходный файл — реализация.

## Передача параметров: три способа

Вот теперь главное место главы. Когда мы пишем:

```cpp
int square(int x) {
    return x * x;
}

int main() {
    int n = 5;
    int r = square(n);
}
```

Что происходит с `n` при вызове `square(n)`? Передаётся **сама переменная** `n`? Или её копия? Или ссылка на неё?

В C++ есть **три** способа передачи параметров. Каждый со своим синтаксисом, своим смыслом, своей ценой.

### Способ 1: по значению

Самый простой и самый частый. Параметр — обычная переменная.

```cpp
void increment(int x) {
    x = x + 1;
    std::cout << "Внутри функции x = " << x << "\n";
}

int main() {
    int a = 5;
    increment(a);
    std::cout << "После вызова a = " << a << "\n";
}
```

Вывод:
```
Внутри функции x = 6
После вызова a = 5
```

**`a` не изменилась!** Хотя мы написали `x = x + 1` внутри функции — менялось значение `x`, а `x` — это **копия** значения `a`, отдельная переменная. Внутри функции получили копию, поработали с ней, копия исчезла при возврате.

Это **передача по значению** (pass by value). Главные свойства:

- Параметр — это **новая переменная**, инициализированная значением аргумента.
- Изменения параметра внутри функции **не видны снаружи**.
- Происходит **копирование**. Для `int` — копия одного слова, мгновенно. Для большого `std::vector<std::string>` — копия всего содержимого, может быть мегабайтами.

Передача по значению — основная по умолчанию для «маленьких» типов: `int`, `double`, `bool`, `char`, маленькие структуры.

### Способ 2: по ссылке

Если хотим, чтобы функция меняла оригинал — берём параметр **по ссылке**:

```cpp
void increment(int& x) {       // обратите внимание: int& x, а не int x
    x = x + 1;
}

int main() {
    int a = 5;
    increment(a);
    std::cout << "a = " << a << "\n";   // a = 6 !
}
```

Знак `&` после типа параметра — **это ссылка**. `int& x` означает «`x` — это другое имя для переменной, которая будет передана при вызове». Внутри функции `x` и снаружи `a` — это **одна и та же переменная**, доступная под двумя именами. Никаких копий.

Когда вы пишете `x = x + 1` — меняется именно `a`.

Ссылка — это **псевдоним**. Аналогии:
- В русском языке у Петра Ильича Чайковского можно сказать «Чайковский» или «Петя» — это одно лицо. Ссылка — это «Петя», обычное имя — «Чайковский».
- В файловой системе бывают символические ссылки — два пути, ведущие к одному файлу.

### Ключевые свойства ссылок

1. **Ссылка должна быть инициализирована при создании.** Нельзя `int& r;` без значения — ошибка.

```cpp
int x = 5;
int& r = x;   // OK: r это псевдоним x
int& r2;       // ОШИБКА: ссылка должна быть инициализирована
```

2. **Ссылка нельзя «перенаправить» на другую переменную.** После создания она навсегда указывает на ту же.

```cpp
int x = 5;
int y = 10;
int& r = x;    // r это x
r = y;         // НЕ перенаправление! Это присваивание: x теперь равен 10
```

В отличие от указателей (ниже) — ссылка после создания «приклеена» намертво.

3. **К ссылке относятся как к самой переменной.** `r * 2` — это `x * 2`. `++r` — это `++x`. И так далее.

### По ссылке для эффективности

Главная причина передавать **большие** объекты по ссылке — **не делать копию**:

```cpp
void print(const std::vector<int>& v) {     // const ссылка — нет копии, нет модификации
    for (int x : v) {
        std::cout << x << "\n";
    }
}
```

`const std::vector<int>&` — это «константная ссылка на вектор». Без копирования (вектор может быть мегабайтным!), и при этом гарантия: внутри функции его не изменят.

**Правило**: если параметр — большой тип (`std::string`, `std::vector`, класс), и функция его не меняет — передавайте `const T&`. Не `T` (будет копия), не `T&` (без `const` — функция может «случайно» поменять).

Маленькие типы (`int`, `double`, `bool`) — по значению. Копия дешёвая, и компилятор всё равно положит копию в регистр.

### Способ 3: по указателю

Указатель — это переменная, в которой лежит **адрес** другой переменной. Это уже не псевдоним, а явная «координата» другой переменной в памяти.

```cpp
void increment(int* p) {       // int* — указатель на int
    *p = *p + 1;                // *p — значение по адресу p
}

int main() {
    int a = 5;
    increment(&a);              // &a — адрес a
    std::cout << "a = " << a << "\n";   // a = 6
}
```

Тут много нового. Разбираем.

- **`int*`** в типе параметра — это «указатель на int». То есть «адрес какой-то ячейки памяти, в которой лежит int».
- **`&a`** при вызове — оператор **«взять адрес»**. Возвращает адрес переменной `a`. Тип — `int*`.
- **`*p`** внутри функции — оператор **«разыменовать»**. Возвращает значение по адресу `p`. То есть `a`.
- **`*p = *p + 1`** — взять значение по адресу `p`, прибавить 1, и положить обратно по тому же адресу. То есть меняем `a`.

### Указатель vs ссылка

Указатели и ссылки делают **похожую** работу — позволяют функции работать с оригиналом, а не с копией. Отличия:

1. **Указатель — это число (адрес).** Ссылка — псевдоним. Указатель занимает 8 байт (на 64-битной системе), ссылка — формально ноль (компилятор её обычно реализует как тот же указатель, но это деталь).

2. **Указатель может быть `nullptr`** — «никуда не указывающий». Ссылку нельзя инициализировать «ничем».

3. **Указатель можно перенаправлять** — `p = &b;` меняет, на что указывает. Ссылку — нельзя.

4. **Для вызова с указателем нужен `&` у вызывающего и `*` для разыменования** — синтаксис заметнее. Со ссылкой — вызов выглядит как обычный.

5. **Указатели — наследие C.** Они везде в C-коде и в системных API. Ссылки — изобретение C++, в C их нет.

### Когда что использовать

Если **обязательно** есть что передать (значение точно есть) и функция должна его менять или эффективно прочитать — **ссылка**. Кратко, безопасно.

Если параметр **может отсутствовать** (тогда передаём `nullptr`) или нужно по C-API — **указатель**.

```cpp
// "Дай мне строку, я её обработаю":
void process(const std::string& s);

// "Дай мне строку, ИЛИ ничего":
void process(const std::string* s) {
    if (s == nullptr) {
        std::cout << "Нет строки\n";
    } else {
        // обработка
    }
}
```

В современном C++17+ для «опционального» параметра обычно используют `std::optional`, но до этого далеко. На C++11 — либо указатель, либо специальные значения.

### Сводная таблица

| Способ | Синтаксис | Можно менять оригинал? | Копирование? |
|--------|-----------|------------------------|--------------|
| По значению | `void f(int x)` | Нет | Да |
| По ссылке | `void f(int& x)` | Да | Нет |
| По const-ссылке | `void f(const int& x)` | Нет | Нет |
| По указателю | `void f(int* p)` | Да | Нет |
| По указателю на const | `void f(const int* p)` | Нет | Нет |

### Правило передачи параметров

Я в начале книги обещал, что буду давать «правила без иффов». Вот оно:

1. **Маленькие типы** (`int`, `double`, `bool`, `char`, маленькие структуры до ~16 байт) — **по значению**.
2. **Большие типы** для чтения — **`const T&`** (по const-ссылке).
3. **Большие типы для модификации** — **`T&`** (по ссылке). Думайте дважды; часто лучше принять копию и вернуть результат.
4. **Указатели** — только когда нужен `nullptr` или для C-API.

Этим правилом обходитесь в 95% случаев.

## Возврат из функции

С возвратом обычно проще, чем с параметрами. По умолчанию — возврат по значению, копия:

```cpp
std::string make_greeting(const std::string& name) {
    return "Hello, " + name + "!";
}

int main() {
    std::string g = make_greeting("Alice");
}
```

Здесь возвращается копия строки. На больших объектах это могло бы быть дорого, но **компилятор почти всегда оптимизирует** через RVO/NRVO (return value optimization) — копии не делается, объект сразу строится в нужном месте. Об этом подробно в главе 19 (move semantics).

Можно возвращать ссылку:

```cpp
int& get_element(std::vector<int>& v, int index) {
    return v[index];
}

int main() {
    std::vector<int> nums = {1, 2, 3};
    get_element(nums, 1) = 99;   // меняет nums[1] на 99
}
```

Опасный приём! Если вернуть ссылку на **локальную переменную** функции — после возврата эта переменная исчезает, ссылка становится «висячей» (dangling), и обращение к ней — UB:

```cpp
int& bad() {
    int local = 42;
    return local;   // ОПАСНО: local исчезает, ссылка указывает в никуда
}

int x = bad();   // x получает мусор или программа крашится
```

Современные компиляторы обычно ругаются на такое (`-Wreturn-local-addr`), но не всегда ловят. Поэтому правило: **никогда не возвращайте ссылку или указатель на локальную переменную**.

Возвращать ссылку безопасно, когда:
- Вы возвращаете ссылку на параметр.
- Вы возвращаете ссылку на static-переменную.
- Вы возвращаете ссылку на член класса (об этом в главе 16).

### Несколько возвращаемых значений

В C++ функция возвращает **только одно** значение. Если хочется два — есть несколько вариантов.

**1. Через ссылочные параметры:**
```cpp
void divmod(int a, int b, int& quotient, int& remainder) {
    quotient = a / b;
    remainder = a % b;
}

int main() {
    int q, r;
    divmod(17, 5, q, r);   // q = 3, r = 2
}
```

**2. Через `std::pair`:**
```cpp
#include <utility>

std::pair<int, int> divmod(int a, int b) {
    return std::make_pair(a / b, a % b);
}

int main() {
    auto result = divmod(17, 5);
    std::cout << result.first << " " << result.second;
}
```

`std::pair<int, int>` — стандартная пара. `result.first` — первое значение, `result.second` — второе.

**3. Через `std::tuple` (C++11)** для трёх и больше:
```cpp
#include <tuple>

std::tuple<int, int, int> get_rgb() {
    return std::make_tuple(255, 128, 64);
}

int main() {
    int r, g, b;
    std::tie(r, g, b) = get_rgb();
}
```

В C++17 появились structured bindings — `auto [q, r] = divmod(17, 5);` — но это не наша база.

**4. Через свою структуру** — часто чище всех:
```cpp
struct DivResult {
    int quotient;
    int remainder;
};

DivResult divmod(int a, int b) {
    return {a / b, a % b};
}

int main() {
    DivResult r = divmod(17, 5);
    std::cout << r.quotient;
}
```

Я в книге буду использовать в основном именованные структуры — они яснее.

## Перегрузка функций

В C++ можно иметь **несколько функций с одинаковым именем**, если у них разные параметры:

```cpp
int max(int a, int b) {
    return a > b ? a : b;
}

double max(double a, double b) {
    return a > b ? a : b;
}

int max(int a, int b, int c) {
    return max(max(a, b), c);
}
```

Три функции с именем `max`. Компилятор по типам аргументов выбирает нужную:

```cpp
max(3, 5);          // int max(int, int)
max(3.14, 2.71);    // double max(double, double)
max(1, 2, 3);       // int max(int, int, int)
```

Это **перегрузка** (overloading). Помните манглинг имён из главы 7? Именно для этого компилятор кодирует типы в имена символов — чтобы при линковке три функции `max` были разными `_Z3maxii`, `_Z3maxdd`, `_Z3maxiii`.

Перегрузка различает функции по:
- Количеству параметров.
- Типам параметров.
- `const`-у на параметрах (но обычно не имеет смысла).

Перегрузка **не** различает функции по:
- Типу возвращаемого значения. **Это важно!** Нельзя `int f(int); double f(int);` — компилятор не поймёт, какую из них вы хотите.

Перегрузка хороша, когда логически функции делают «одно и то же» с разными типами. Например, `max`, `min`, `print`, `to_string`. Плоха, когда вы пишете перегрузку, чтобы скрыть разную логику под одним именем — путает читателя.

## Параметры по умолчанию

Можно задать значение **по умолчанию** для параметра:

```cpp
void greet(const std::string& name, const std::string& greeting = "Hello") {
    std::cout << greeting << ", " << name << "!\n";
}

int main() {
    greet("Alice");                // Hello, Alice!
    greet("Bob", "Welcome");        // Welcome, Bob!
}
```

Параметры по умолчанию указываются **с конца**. Нельзя `void f(int a = 5, int b)` — компилятор не поймёт, как вызывать `f(7)` (это `b`? или `a`?).

Если функция объявлена и определена раздельно — параметры по умолчанию **только в объявлении**, не в определении:

```cpp
// math.h
int sum(int a, int b, int c = 0);

// math.cpp
int sum(int a, int b, int c) {   // здесь = 0 НЕ повторять
    return a + b + c;
}
```

Параметры по умолчанию хороши, когда у функции «обычный» случай и редкие особые. Например, в большинстве вызовов вы хотите стандартное приветствие — `greet("Bob")` короче, чем `greet("Bob", "Hello")`. Плохо, когда параметров много и непонятно, какие по умолчанию — лучше отдельные функции или структура с параметрами.

## inline

Когда функция очень короткая (одна-две строки), у вызова есть **накладные расходы**: положить аргументы в регистры/на стек, перепрыгнуть, выполнить, вернуться. Для крохотной функции это может быть дольше самого тела.

Решение — **inline-функция**. Это намёк компилятору: «не делай вызов, подставь тело прямо в место вызова».

```cpp
inline int square(int x) {
    return x * x;
}

int main() {
    int r = square(5);
    // компилятор подставит это как:
    // int r = 5 * 5;
}
```

Это называется **инлайнинг** (inlining). После него — никакого вызова функции, просто выражение.

Тонкость: `inline` в современном C++ — **слабая** рекомендация. Компилятор сам решает, инлайнить или нет, и без `inline` тоже может. Но `inline` важен по другой причине — **он разрешает определение в заголовочном файле**:

```cpp
// math.h
#ifndef MATH_H
#define MATH_H

inline int square(int x) {
    return x * x;
}

#endif
```

Без `inline` это привело бы к ошибке `multiple definition` при линковке — потому что заголовок включается в несколько `.cpp`, и компилируется в каждый. С `inline` линкер знает: «это определение, оно может быть в нескольких файлах одинаковое, выбери одно».

В простых случаях — пишите функцию в `.cpp`, не в `.h`. Если выяснилось, что для шаблона или производительности нужно в `.h` — добавьте `inline`.

## Рекурсия

Функция может вызывать **сама себя**. Это **рекурсия**:

```cpp
int factorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}
```

`factorial(5)` вызывает `factorial(4)`, который вызывает `factorial(3)`, который вызывает `factorial(2)`, который вызывает `factorial(1)`. Последний возвращает 1, дальше — `2 * 1`, `3 * 2`, `4 * 6`, `5 * 24` = 120.

Главное в рекурсии — **base case** (базовый случай). Условие выхода, при котором функция возвращается без рекурсивного вызова. У нас это `if (n <= 1) return 1;`. Без base case рекурсия бесконечная.

Каждый рекурсивный вызов кладёт на стек новый кадр (как мы обсуждали в главе 7). Размер стека ограничен (обычно 8 MB на Linux/macOS, 1 MB на Windows). Когда рекурсия слишком глубокая — **stack overflow**, программа падает.

```cpp
int infinite_recursion(int x) {
    return infinite_recursion(x);   // никогда не остановится
}
```

На моей машине это падает где-то на 200 000-й итерации.

Рекурсия — мощный инструмент. Многие задачи естественно рекурсивные:
- Обход дерева: посетить корень, потом рекурсивно обход левого поддерева, потом правого.
- Алгоритм поиска в файловой системе: открыть папку, для каждого элемента — если файл, обработать; если папка, рекурсивно зайти.
- Алгоритмы делящие задачу пополам — quicksort, mergesort, binary search.

Но рекурсии не везде стоит верить. Иногда итеративная версия (через цикл) быстрее и не рискует переполнить стек:

```cpp
int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}
```

Это эквивалентно рекурсивной версии, но без стека. Для факториала такая форма обычно лучше.

### Хвостовая рекурсия

Один особый вид рекурсии — **хвостовая**: рекурсивный вызов — последняя операция в функции. Например:

```cpp
int sum_recursive(int n, int acc) {
    if (n == 0) return acc;
    return sum_recursive(n - 1, acc + n);
}

// sum_recursive(100, 0) даёт сумму 1+2+...+100 = 5050
```

В хвостовой рекурсии нет «работы» после рекурсивного вызова. Поэтому теоретически компилятор может заменить такой вызов прыжком — без расхода стека. Это называется **tail call optimization (TCO)**. C++-компиляторы её обычно делают (с включёнными оптимизациями), но не гарантируют. Языки типа Scheme, Haskell — гарантируют. В C++ для гарантированной безстековой рекурсии нужно переписать в цикл.

## Forward declaration

Иногда две функции должны вызывать друг друга:

```cpp
bool is_even(int n);   // forward declaration

bool is_odd(int n) {
    if (n == 0) return false;
    return is_even(n - 1);
}

bool is_even(int n) {
    if (n == 0) return true;
    return is_odd(n - 1);
}
```

`is_odd` использует `is_even`, который определён ниже. Без объявления вверху компилятор бы выдал ошибку «is_even not declared». Объявление-«обещание» снимает проблему.

(Алгоритм этот — учебный, в реальной жизни `n % 2 == 0` куда проще. Зато он показывает паттерн взаимной рекурсии.)

## main — особая функция

`main` — точка входа в программу. Особенности:

- **Возвращает `int`**. Это код выхода: 0 — успех, ненулевой — ошибка.
- **Опускать `return 0;`** разрешено — компилятор подставит сам. Я предпочитаю писать явно.
- **Может принимать аргументы командной строки**:

```cpp
int main(int argc, char* argv[]) {
    std::cout << "Количество аргументов: " << argc << "\n";
    for (int i = 0; i < argc; ++i) {
        std::cout << "  argv[" << i << "] = " << argv[i] << "\n";
    }
    return 0;
}
```

`argc` (argument count) — сколько аргументов передано (включая имя программы). `argv` (argument vector) — массив строк (на самом деле — массив `char*`-указателей).

```bash
$ ./program hello world 42
Количество аргументов: 4
  argv[0] = ./program
  argv[1] = hello
  argv[2] = world
  argv[3] = 42
```

Мы будем это использовать в проектах — например, `./chat-server --port 9001` или `./grep "pattern" file.txt`.

## Лямбды — короткое упоминание

В C++11 появились **лямбды** — функции, объявляемые «прямо на месте»:

```cpp
auto add = [](int a, int b) { return a + b; };
std::cout << add(3, 4);   // 7
```

Это огромная тема, мы её разберём в главе 21 на проекте RPG. Сейчас просто знайте — такая штука есть.

## Указатели на функции

Можно сохранить функцию в переменную и вызвать через неё:

```cpp
int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }

int main() {
    int (*op)(int, int);   // указатель на функцию, принимающую (int, int) и возвращающую int
    op = add;
    std::cout << op(5, 3) << "\n";   // 8
    op = sub;
    std::cout << op(5, 3) << "\n";   // 2
}
```

Синтаксис уродливый. Обычно вместо него используют `std::function` (про неё в главе 21) или `auto`:

```cpp
auto op = add;   // тип выводится
op(5, 3);
```

Указатели на функции редко нужны в современном C++. Но они есть, и в чужом коде встречаются.

## Чистые функции и побочные эффекты

Функция **чистая** (pure), если:
- Её результат зависит **только от параметров**.
- Она **не меняет** ничего снаружи (никаких глобалов, никакого ввода-вывода, ничего).

```cpp
int square(int x) { return x * x; }   // чистая
```

Чистая, потому что: возвращает `x*x` (зависит только от `x`), ничего не меняет.

**Не чистая**:

```cpp
int counter = 0;

int increment_and_return() {
    counter = counter + 1;   // меняет глобал
    return counter;
}
```

Вызов два раза подряд даёт разные результаты — функция «помнит» состояние.

Чистые функции хороши:
- **Тестируются легко** — нет внешних зависимостей.
- **Параллелятся** — нет общего состояния, безопасно запускать в разных потоках.
- **Кэшируются** — если результат уже посчитан, можно его запомнить.
- **Читаются** — поведение полностью описано сигнатурой.

В C++ принудить функцию быть чистой нельзя (нет такого ключевого слова), но писать **по возможности чисто** — хороший стиль. Особенно для «вычислительных» функций. С побочными эффектами лучше работать в маленьких островках; остальной код пусть будет чистым.

## Большой пример: банковская симуляция

Соберём всё в осмысленную программу. Сделаем подобие банка: счета и операции над ними.

```cpp
#include <iostream>
#include <string>

struct Account {
    std::string owner;
    double balance;
};

// Чистая функция: вычисляет процент
double calculate_interest(double balance, double rate) {
    return balance * rate;
}

// Изменяет счёт (передача по ссылке)
void deposit(Account& account, double amount) {
    account.balance = account.balance + amount;
}

// Возвращает true если перевод прошёл, false если денег не хватило
bool transfer(Account& from, Account& to, double amount) {
    if (from.balance < amount) {
        return false;
    }
    from.balance = from.balance - amount;
    to.balance = to.balance + amount;
    return true;
}

// Только читает (const-ссылка)
void print(const Account& account) {
    std::cout << "Счёт " << account.owner << ": " << account.balance << "\n";
}

// Перегрузки — для разных типов суммы
void print(const Account& account, double amount) {
    std::cout << "Счёт " << account.owner << ": " << account.balance
              << " (сумма операции: " << amount << ")\n";
}

int main() {
    Account alice{"Alice", 1000.0};
    Account bob{"Bob", 500.0};
    
    print(alice);
    print(bob);
    
    std::cout << "\nДепозит 200 на счёт Alice\n";
    deposit(alice, 200);
    print(alice);
    
    std::cout << "\nПеревод 300 от Alice к Bob\n";
    if (transfer(alice, bob, 300)) {
        std::cout << "OK\n";
    } else {
        std::cout << "Недостаточно средств\n";
    }
    print(alice);
    print(bob);
    
    std::cout << "\nПеревод 999999 от Alice к Bob\n";
    if (transfer(alice, bob, 999999)) {
        std::cout << "OK\n";
    } else {
        std::cout << "Недостаточно средств\n";
    }
    print(alice);
    
    constexpr double annual_rate = 0.05;
    double interest = calculate_interest(alice.balance, annual_rate);
    std::cout << "\nГодовые Alice по ставке " << annual_rate
              << ": " << interest << "\n";
    
    return 0;
}
```

Соберите:

```bash
$ g++ -std=c++11 -Wall -Wextra bank.cpp -o bank
$ ./bank
```

Тут использовано:
- `struct` — для определения типа `Account` (узнаем подробнее в главе 16).
- Передача по значению (`double amount`).
- Передача по ссылке (`Account& from`).
- Передача по const-ссылке (`const Account& account`).
- Перегрузка (две функции `print`).
- Чистая функция (`calculate_interest`).
- Возврат `bool` для индикации успеха.
