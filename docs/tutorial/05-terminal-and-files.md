# Глава 5. Терминал, файлы, папки, права

К этой главе у вас в голове должны лежать: что такое компьютер (глава 1), как кодируются числа и текст (глава 2), что такое программа и компиляция (глава 3), и как думать алгоритмически (глава 4). Последняя глава Части 0а — про **терминал**, командную строку. Без него C++-разработка невозможна: вы будете жить в терминале. Если вы привыкли работать только мышкой и боитесь чёрного окна — после этой главы перестанете.

## Что такое терминал

**Терминал** (он же «консоль», «командная строка», «shell») — это **текстовый интерфейс к компьютеру**. Вместо того чтобы тыкать мышкой в иконки, вы пишете текстовые команды, нажимаете Enter, и компьютер выполняет.

Зачем нужен текстовый интерфейс, если есть удобный графический? Несколько причин.

**Скорость.** Опытный программист в терминале делает за секунду то, на что в графическом интерфейсе ушли бы 10-20 секунд кликов. Например, скопировать все `.cpp` файлы из одной папки в другую: команда `cp *.cpp /target/folder/` — секунда. Через Finder/Explorer: открыть две папки, выделить нужные файлы (а ещё мышкой выделить только .cpp без других — отдельная морока), нажать Cmd+C, перейти в другую папку, Cmd+V. Минут пять.

**Автоматизация.** Команды можно объединять в скрипты. Один раз написал «делай это, потом это, потом это» — и в следующий раз запускаешь скрипт одной командой. Мышкой такое не записать.

**Воспроизводимость.** Если я в книге напишу «открой Finder, нажми сюда, потом сюда» — у вас может быть другая версия macOS, и кнопки могут стоять иначе. А команда `ls -la` одинакова и сегодня, и десять лет назад, на любой системе.

**Удалённая работа.** Серверы (где хостится ваш сайт, например) обычно не имеют графической оболочки — только командная строка через SSH. Если хотите работать с серверами — терминал обязателен.

**Программирование требует.** Все компиляторы C++, все системы сборки, все системы контроля версий (git) — это инструменты командной строки. Графические обёртки есть, но они скрывают то, что внутри, и мешают понять, что происходит.

Не пугайтесь чёрного окна. Сначала медленно, потом быстро.

## Где он живёт

**macOS.** Программа называется **Terminal** (или **iTerm2**, более продвинутая бесплатная альтернатива; рекомендую поставить через `brew install --cask iterm2`). Открыть: Cmd+Space, набрать «terminal», Enter.

**Linux.** На Ubuntu это **GNOME Terminal**, на других дистрибутивах могут быть **Konsole**, **xterm**, **alacritty**. Обычно открывается сочетанием Ctrl+Alt+T или через меню приложений.

**Windows.** Тут несколько вариантов. **PowerShell** или **Windows Terminal** (новое приложение от Microsoft, рекомендую) — это «нативные» терминалы Windows. Но их синтаксис команд отличается от Unix-овского (macOS/Linux). Для нашей книги проще установить **WSL2** (Windows Subsystem for Linux) — это полноценный Linux внутри Windows, и тогда команды будут такие же, как в этой главе. В главе 6 мы про это поговорим подробнее. Пока, если вы на Windows и читаете эту главу, я рекомендую: либо примите, что некоторые команды у вас будут отличаться, либо поставьте WSL2 (это 10 минут установки).

## Приглашение к вводу (prompt)

Когда вы открываете терминал, видите примерно такое:

```
serik@MacBook-Pro ~ %
```

Или такое:

```
serik@ubuntu:~$
```

Это **приглашение** (prompt). Оно состоит из:
- `serik` — имя пользователя (вашей учётной записи в системе).
- `MacBook-Pro` или `ubuntu` — имя компьютера.
- `~` — текущая папка (тильда = домашняя папка пользователя, об этом ниже).
- `%` или `$` — символ конца приглашения. После него ждётся ваша команда.

Когда я в книге пишу:
```bash
$ ls
```

Знак `$` — это и есть приглашение. Команда — `ls`. Сам `$` вы не вводите.

После того, как набрали команду и нажали Enter — терминал передаёт её специальной программе, которая называется **shell** (по-русски «оболочка»). Самые популярные шеллы:
- **bash** — Bourne Again SHell, стандартный во многих Linux-дистрибутивах. Старый, но мощный.
- **zsh** — Z Shell. С macOS Catalina (2019) это шелл по умолчанию на Mac. Совместим с bash, плюс много улучшений.
- **fish** — Friendly Interactive Shell. Удобный, с автодополнением, но синтаксис чуть отличается.

В этой книге я пишу под bash/zsh; команды работают одинаково.

## Где я нахожусь — `pwd`

Каждый раз, когда вы в терминале, вы находитесь **в какой-то папке**. Все команды выполняются в контексте этой папки. Команда `pwd` (print working directory) показывает, где вы сейчас:

```bash
$ pwd
/Users/serik
```

На macOS домашняя папка — `/Users/<имя>`. На Linux — `/home/<имя>`. На Windows (WSL) — что-то вроде `/home/serik`, но «настоящие» Windows-файлы можно найти под `/mnt/c/Users/<имя>`.

## Что в папке — `ls`

Команда `ls` (list) показывает содержимое текущей папки.

```bash
$ ls
Desktop  Documents  Downloads  Music  Pictures
```

Без аргументов выводит просто имена. С флагом `-l` («длинный формат») — много деталей:

```bash
$ ls -l
total 0
drwx------+   5 serik  staff    160 Apr 10 14:22 Desktop
drwx------+   3 serik  staff     96 Mar 22 09:30 Documents
drwx------+   8 serik  staff    256 May 11 11:00 Downloads
...
```

Расшифровка одной строки:
- `drwx------+` — права доступа (об этом ниже).
- `5` — количество ссылок на файл (для папок — что-то техническое, не важно).
- `serik` — владелец.
- `staff` — группа владельца.
- `160` — размер в байтах.
- `Apr 10 14:22` — дата изменения.
- `Desktop` — имя.

С флагом `-a` (all) показываются **скрытые файлы** — те, чьи имена начинаются с точки:

```bash
$ ls -a
.   .bash_profile  .gitconfig  Desktop  Downloads
..  .DS_Store      .ssh        Documents  Music
```

`.` — текущая папка (всегда есть). `..` — родительская папка. `.bash_profile`, `.gitconfig` — конфиги, которые системные программы прячут от глаз, потому что они не для постоянного редактирования.

Можно комбинировать флаги: `ls -la` или `ls -al` — длинный формат и включая скрытые.

## Перемещение — `cd`

Команда `cd` (change directory) переходит в другую папку:

```bash
$ pwd
/Users/serik
$ cd Documents
$ pwd
/Users/serik/Documents
$ ls
report.pdf  notes.txt
```

`cd <папка>` — перейти в подпапку. Чтобы вернуться обратно:

```bash
$ cd ..
$ pwd
/Users/serik
```

`..` — это «на уровень выше». Можно поднимать на несколько уровней: `cd ../..` — на два уровня вверх.

`cd` без аргументов — вернуться в домашнюю папку:

```bash
$ cd
$ pwd
/Users/serik
```

Эквивалент — `cd ~`. Тильда `~` означает «домашняя папка».

Можно прыгать сразу в любое место по абсолютному пути:

```bash
$ cd /Users/serik/Desktop/cpp-from-scratch
$ pwd
/Users/serik/Desktop/cpp-from-scratch
```

## Пути — абсолютные и относительные

Это важная концепция, на ней спотыкаются почти все новички.

**Абсолютный путь** — начинается с корня файловой системы и однозначно указывает на файл/папку. На Unix это что-то вроде `/Users/serik/Desktop/photo.jpg` — начинается со слеша.

**Относительный путь** — указывает на файл/папку относительно текущей. Например, если вы сейчас в `/Users/serik`, то `Desktop/photo.jpg` — это относительный путь, и он указывает на тот же файл, что абсолютный путь `/Users/serik/Desktop/photo.jpg`.

Специальные относительные пути:
- `.` — текущая папка («здесь»).
- `..` — родительская папка («на уровень выше»).
- `~` — домашняя папка.

Примеры. Вы в `/Users/serik/Desktop/cpp-from-scratch/docs/tutorial`:

| Путь | На что указывает |
|------|------------------|
| `00-intro.md` | `/Users/serik/Desktop/cpp-from-scratch/docs/tutorial/00-intro.md` |
| `./00-intro.md` | то же самое (явно «здесь») |
| `../tutorial-original/file.md` | соседняя папка |
| `../../README.md` | `/Users/serik/Desktop/cpp-from-scratch/README.md` |
| `~/Downloads/photo.jpg` | `/Users/serik/Downloads/photo.jpg` |
| `/etc/hosts` | `/etc/hosts` (абсолютный) |

Относительные пути удобны, когда вы работаете в одном проекте: писать `src/main.cpp` короче, чем `/Users/serik/Desktop/myproject/src/main.cpp`. Абсолютные пути нужны, когда хочется указать на что-то «глобальное» — например, `/usr/bin/g++` (системный компилятор) или `/var/log/system.log` (системный лог).

## Создать папку — `mkdir`

```bash
$ cd ~
$ mkdir my-project
$ ls
my-project  Desktop  Documents  ...
```

`mkdir <имя>` создаёт папку. Если папка уже есть — выдаёт ошибку.

С флагом `-p` создаются все промежуточные папки:

```bash
$ mkdir -p projects/2026/cpp/lesson-01
$ ls projects/2026/cpp/
lesson-01
```

Если флага `-p` нет, и какой-то промежуточной папки нет — `mkdir` выдаст ошибку.

## Создать или открыть файл

Чтобы создать пустой файл, есть команда `touch`:

```bash
$ touch hello.cpp
$ ls
hello.cpp
```

Если файла не было — создаётся пустой. Если был — обновляется его «время последнего изменения», содержимое не трогается. Это редко нужно в реальной работе, но команда полезная.

Чаще файлы создаются через редактор. Я писал в главе 1 (или, в новой нумерации, в главе 6, которую вы скоро прочтёте), что лучший редактор для нас — VS Code. Чтобы открыть файл в VS Code из терминала:

```bash
$ code hello.cpp
```

Если файла нет — VS Code откроется с пустым новым файлом этого имени. Сохраните (Cmd+S) — файл создастся.

## Прочитать файл — `cat`

`cat` (concatenate) выводит содержимое файла в терминал:

```bash
$ cat hello.cpp
#include <iostream>

int main() {
    std::cout << "Hello, world!" << std::endl;
    return 0;
}
```

Для маленьких файлов хорошо. Для огромных — терминал захлебнётся (потому что весь файл напечатается за раз).

Если файл большой, лучше использовать `less`:

```bash
$ less BIG.txt
```

Откроется «листалка» — можно листать стрелками или PgUp/PgDn, поиск через `/`, выход — `q`. Это удобнее, чем `cat`, для логов и больших текстовых данных.

И ещё две полезные:
- `head <файл>` — выводит первые 10 строк (можно задать другое число: `head -n 5`).
- `tail <файл>` — выводит последние 10 строк.

Особо полезно: `tail -f <файл>` — выводит новые строки по мере их добавления в файл. Используется для слежения за логами в реальном времени.

## Копировать, перемещать, удалять — `cp`, `mv`, `rm`

```bash
$ cp source.cpp backup.cpp
```

Копирует. Был `source.cpp`, теперь есть `source.cpp` и `backup.cpp` с тем же содержимым.

```bash
$ mv old-name.cpp new-name.cpp
```

Переименовывает (или перемещает в другую папку). Не оставляет копии.

```bash
$ rm file.txt
```

Удаляет. Будьте осторожны: в терминале **нет корзины**. Удалённое — удалено навсегда. Особенно опасно `rm -rf <папка>` — удаляет папку со всем содержимым рекурсивно, без подтверждения. Команда `rm -rf /` на Unix-системе с правами root в худшем случае стирает всё. Никогда не запускайте таких вещей бездумно.

С флагом `-r` (recursive) можно копировать или удалять папки:

```bash
$ cp -r my-project my-project-backup
$ rm -r old-project
```

Без `-r` `cp` или `rm` папку не возьмут — нужно явно сказать «да, я хочу с подпапками».

С флагом `-i` (interactive) команды спрашивают подтверждение перед каждым действием:

```bash
$ rm -i file.txt
remove file.txt? y
```

Полезная страховка для опасных операций.

## Маски (wildcards)

Вместо имени файла можно использовать **маску** — шаблон с подстановочными символами.

Самый частый — `*` (звёздочка). Она означает «любое количество любых символов».

```bash
$ ls *.cpp           # все .cpp файлы в текущей папке
$ rm *.tmp           # удалить все .tmp файлы
$ cp src/*.cpp build/   # скопировать все .cpp из src в build
```

Менее частый — `?`. Это «ровно один любой символ»:

```bash
$ ls file?.txt
file1.txt  file2.txt  fileX.txt
```

Маски разворачиваются **самим шеллом до запуска команды**. То есть когда вы пишете `rm *.tmp`, шелл сначала находит все `.tmp` файлы (например, `a.tmp` и `b.tmp`), и фактически выполняется `rm a.tmp b.tmp`. Сама программа `rm` про звёздочку не знает. Это важно помнить — иногда у вас не сработает что-то по маске именно потому, что шелл подставил пустой список.

## Права доступа

В выводе `ls -l` мы видели:

```
-rw-r--r--  1 serik  staff   1024  May 11 21:00  notes.txt
drwxr-xr-x  3 serik  staff     96  May 11 21:00  my-project
```

Первый «столбец» из 10 символов — это **права доступа**. Разберём.

**Первый символ** — тип объекта:
- `-` — обычный файл;
- `d` — папка (directory);
- `l` — символическая ссылка;
- `b`, `c`, `s`, `p` — специальные файлы (устройства, сокеты).

**Следующие 9 символов** — три группы по 3:
- Первая тройка — права **владельца** файла.
- Вторая — права **группы** владельца.
- Третья — права **всех остальных**.

В каждой тройке три буквы:
- `r` — read (можно читать).
- `w` — write (можно изменять).
- `x` — execute (можно выполнить; для папки — войти внутрь).

Если права нет — стоит `-`.

Примеры:
- `-rw-r--r--`: обычный файл. Владелец читает и пишет, остальные только читают.
- `-rwxr-xr-x`: обычный файл, исполняемый. Все могут запустить, владелец может ещё изменить.
- `drwxr-xr-x`: папка. Все могут войти и читать, владелец может ещё изменять содержимое.
- `-rw-------`: обычный файл, только владелец может читать и писать. Другие — никак. Так выглядят файлы с паролями.

Сразу важный момент. **Чтобы запустить программу — у файла должны быть права `x`.** Когда вы компилируете C++-программу через `g++ hello.cpp -o hello`, компилятор автоматически проставляет `x` на выходном файле. Поэтому `./hello` срабатывает. А если бы прав `x` не было — была бы ошибка «Permission denied».

### `chmod`

Для изменения прав используется `chmod` (change mode).

```bash
$ chmod +x my-script.sh     # добавить право выполнения всем
$ chmod -w file.txt          # снять право записи у всех
$ chmod 644 notes.txt         # установить точно: 6 для владельца, 4 для группы, 4 для остальных
```

Цифры в `chmod 644` — это сложение прав:
- `4` = read,
- `2` = write,
- `1` = execute.

Сумма даёт права тройки:
- `7` = 4+2+1 = `rwx` (всё);
- `6` = 4+2 = `rw-` (читать и писать);
- `5` = 4+1 = `r-x` (читать и выполнять);
- `4` = `r--` (только читать);
- `0` = `---` (ничего).

`chmod 755 file` — владельцу `rwx`, остальным `r-x`. Обычно так выставляют для скриптов и программ.

`chmod 644 file` — владельцу `rw-`, остальным `r--`. Обычно для обычных файлов.

### `chown`

Меняет владельца файла:

```bash
$ sudo chown serik myfile.txt
```

Это редко нужно в обычной разработке, но на серверах часто встречается.

## Переменные окружения

В терминале есть **переменные окружения** — что-то вроде глобальных переменных, которые читают программы. Самая важная — `PATH`.

`PATH` — это список папок, в которых шелл ищет программы. Когда вы пишете `g++ file.cpp` — шелл по очереди проверяет: есть ли в `/usr/local/bin/g++`? Если нет, в `/usr/bin/g++`? И так далее. Список папок — это и есть `PATH`.

Посмотреть его содержимое:

```bash
$ echo $PATH
/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
```

Папки разделены двоеточием. Команда `echo` просто выводит то, что ей дают. Знак `$` перед именем переменной означает «возьми её значение».

Другие важные переменные:
- `HOME` — путь к домашней папке (`/Users/serik` или `/home/serik`).
- `USER` — имя текущего пользователя.
- `SHELL` — путь к используемому шеллу.
- `LANG` — текущая локаль (например, `ru_RU.UTF-8` или `en_US.UTF-8`).

Установить свою переменную:

```bash
$ MY_VAR=hello
$ echo $MY_VAR
hello
```

Но эта переменная видна **только в текущем терминале**. Когда закроете и откроете заново — её не будет. Чтобы сделать постоянной, надо добавить в файл `~/.bashrc` (для bash) или `~/.zshrc` (для zsh) строку `export MY_VAR=hello`.

В разработке часто пользуются переменными окружения для конфигурации программ. Например, программа может читать `DATABASE_URL` и подключаться к БД по этому адресу. Это удобно для разных окружений (dev/staging/prod) и для секретов (не хранить пароли в коде).

## Перенаправление и пайпы

Это одна из самых мощных штук в Unix-философии. Расскажу основы; в проекте Mini-shell (Часть III) мы будем строить такое сами.

### Стандартные потоки

У каждой программы есть три «стандартных канала»:
- **stdin** (standard input) — стандартный ввод. Откуда программа читает данные. По умолчанию — клавиатура.
- **stdout** (standard output) — стандартный вывод. Куда программа пишет результат. По умолчанию — терминал.
- **stderr** (standard error) — стандартный поток ошибок. Куда программа пишет сообщения об ошибках. По умолчанию — тоже терминал.

Эти каналы можно **перенаправлять**.

### Запись stdout в файл — `>`

```bash
$ ls > files.txt
```

Вместо вывода на экран `ls` пишет результат в файл `files.txt`. Если файл был — перезаписывается. Чтобы добавить в конец, не перезаписывая:

```bash
$ ls >> files.txt
```

`>>` дописывает к существующему файлу.

### Чтение stdin из файла — `<`

```bash
$ sort < unsorted.txt
```

Команда `sort` (которая обычно ждёт данные с клавиатуры или из аргументов) теперь читает из файла `unsorted.txt`.

### Пайпы — `|`

Самое мощное — соединять вывод одной программы со входом другой:

```bash
$ ls | sort
```

Вывод `ls` идёт во вход `sort`. Получается отсортированный список файлов.

Можно цеплять несколько подряд:

```bash
$ cat names.txt | grep "Иван" | sort | uniq -c
```

Что произойдёт:
1. `cat names.txt` — вывести содержимое файла.
2. `grep "Иван"` — отфильтровать строки, содержащие «Иван».
3. `sort` — отсортировать оставшиеся.
4. `uniq -c` — подсчитать дубликаты.

Каждая программа делает одну простую вещь, но соединяя их в цепочку — получаем сложную обработку. Это и есть **Unix-философия**: маленькие инструменты, делающие одно дело хорошо, и комбинирование их через пайпы.

## Запуск программы и `./`

Вспомним из главы 6 (или из первой версии главы 1): чтобы запустить программу из текущей папки, надо написать `./hello`, а не просто `hello`.

Почему?

Когда вы пишете `hello`, шелл ищет программу с этим именем **в папках из `PATH`**. Текущую папку — **не** проверяет. Это сделано из соображений безопасности: представьте, вы скачали архив с какой-то программы, распаковали в `/tmp`, перешли туда, и набрали `ls` — вместо системного `ls` шелл мог бы запустить злонамеренный `ls`, лежащий в архиве. Поэтому текущая папка в `PATH` не входит (на Unix; на Windows входит, и поэтому Windows исторически уязвимее).

`./hello` явно говорит: запустить программу `hello` из текущей папки (`.`). Точка тут — та же самая, что в `cd .` или `ls .` — означает «здесь».

Если хотите запустить программу из другой папки, можно указать путь:

```bash
$ /Users/serik/Desktop/cpp-from-scratch/demo-rpg/game
```

Или относительный путь:

```bash
$ ../demo-rpg/game
```

Если вы регулярно используете какую-то программу, её путь добавляют в `PATH`, и тогда можно вызывать просто по имени.

## История команд

Шелл запоминает все команды, которые вы вводили. Чтобы вернуться к предыдущей — стрелка вверх. Ещё раз — позапрошлая. Стрелка вниз — обратно к новым.

Поиск по истории: Ctrl+R, потом начинаете печатать — шелл находит последнюю команду, начинающуюся с этого. Очень удобно.

История хранится в файле `~/.bash_history` или `~/.zsh_history`. Можно её отредактировать руками или экспортировать.

## Автодополнение

Нажмите Tab — шелл попробует дополнить незаконченное слово. Например, набираете:

```bash
$ cd Desk<Tab>
```

И шелл сам допишет до `cd Desktop/`. Если вариантов несколько — Tab покажет их все. Это в десятки раз ускоряет работу — не приходится точно набирать длинные имена.

## Очистить экран

Когда терминал засыпан выводом — Ctrl+L (или команда `clear`) очищает экран. Полезно, чтобы перевести дух.

## Прервать команду

Запустили долгую команду и поняли, что не то? Ctrl+C — прервать (программа получает сигнал `SIGINT`).

Ctrl+Z — приостановить (программа замораживается). Чтобы продолжить в фоне — `bg`. Чтобы продолжить на переднем плане — `fg`. Эту функциональность мы будем плотно изучать в проекте Mini-shell.

## Полезный набор команд

Сохраню сюда «карманный справочник», к которому буду отсылать в следующих главах:

| Команда | Что делает |
|---------|-----------|
| `pwd` | где я сейчас |
| `ls` | что в этой папке |
| `ls -la` | то же, с деталями и скрытыми файлами |
| `cd <папка>` | перейти в папку |
| `cd ..` | подняться на уровень выше |
| `cd ~` или `cd` | в домашнюю папку |
| `mkdir <имя>` | создать папку |
| `mkdir -p <путь>` | создать все промежуточные |
| `touch <имя>` | создать пустой файл |
| `cat <файл>` | показать файл |
| `less <файл>` | пролистать большой файл |
| `head <файл>` | первые 10 строк |
| `tail <файл>` | последние 10 строк |
| `tail -f <файл>` | следить за новыми строками |
| `cp <откуда> <куда>` | копировать файл |
| `cp -r <откуда> <куда>` | копировать папку рекурсивно |
| `mv <откуда> <куда>` | переместить или переименовать |
| `rm <файл>` | удалить файл |
| `rm -r <папка>` | удалить папку с содержимым |
| `chmod +x <файл>` | сделать исполняемым |
| `echo <текст>` | напечатать в stdout |
| `echo $VAR` | значение переменной |
| `export VAR=value` | установить переменную |
| `grep <текст> <файл>` | найти строки, содержащие текст |
| `wc -l <файл>` | сосчитать строки |
| `find <где> -name <маска>` | поиск файлов |
| `man <команда>` | справка по команде |

Команда `man` — самая полезная. `man ls`, `man chmod`, `man find` — открывает встроенную справку. Выход — `q`. Туда можно лезть всегда, когда не помните флаги.

## Маленькое упражнение

Откройте терминал и сделайте по шагам:

1. Перейдите в домашнюю папку (`cd ~`).
2. Создайте папку `cpp-practice` (`mkdir cpp-practice`).
3. Зайдите в неё (`cd cpp-practice`).
4. Создайте подпапки `src`, `include`, `build` одной командой (`mkdir src include build`).
5. Создайте пустой файл `src/main.cpp` (`touch src/main.cpp`).
6. Посмотрите структуру (`ls -la` или, если установлен, `tree`).
7. Запишите в `src/main.cpp` одно слово через `echo`: `echo "Hello" > src/main.cpp`.
8. Покажите содержимое: `cat src/main.cpp`.
9. Скопируйте файл: `cp src/main.cpp src/backup.cpp`.
10. Удалите бэкап: `rm src/backup.cpp`.
11. Поднимитесь на уровень выше: `cd ..`.
12. Удалите всю папку `cpp-practice` (только если уверены, что не нужно): `rm -r cpp-practice`.

Если всё прошло без ошибок — освоились. Если запутались — повторите спокойнее. После этой главы должно стать комфортно жить в терминале.
